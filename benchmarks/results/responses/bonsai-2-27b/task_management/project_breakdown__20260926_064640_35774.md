# 1. Supuestos del proyecto

## Alcance recomendado

**Incluye:**

- Landing page de una sola página.
- Hero principal.
- Problema / solución.
- Beneficios clave.
- Funcionalidades principales.
- Sección de prueba social o casos de uso.
- Pricing o planes.
- CTA principal: “Probar gratis”, “Pedir demo” o “Unirme a lista de espera”.
- Formulario de contacto o captura de leads.
- FAQ.
- Analíticas básicas.
- SEO básico.
- Responsive.
- Accesibilidad mínima.
- Legal básico: cookies, privacidad, términos.

**No incluye, para no retrasar el lanzamiento:**

- Multi-idioma.
- Video complejo.
- A/B testing avanzado.
- CMS complejo.
- Integraciones profundas con el producto.
- Demo funcional completa dentro de la landing.
- Animaciones avanzadas.

---

## Stack recomendado

Para una landing rápida y escalable:

- **Astro**, **Next.js** o **Nuxt** con **Tailwind CSS**.
- Hosting en **Vercel**, **Netlify**, **Cloudflare Pages** o similar.
- Formulario con **Formspree**, **Resend**, **HubSpot**, **Zoho CRM** o backend propio.
- Analíticas con **Plausible**, **Umami**, **PostHog**, **GA4** o similar.

Si ya usan WordPress, el plan sigue siendo válido, pero los developers deben priorizar velocidad y evitar plugins innecesarios.

# 6. Dependencias críticas

La ruta crítica es:

```text
Brief
→ Estructura
→ Wireframes
→ Copy base
→ Aprobación
→ Diseño hi-fi
→ Copy final
→ Aprobación final
→ Desarrollo
→ Staging
→ QA
→ Deploy
→ Lanzamiento
```

En detalle:

| Dependencia | Impacto si se retrasa |
|---|---|
| Brief no aprobado | No se puede diseñar ni escribir |
| Wireframes no aprobados | Diseño puede desviarse |
| Copy final no listo | Desarrollo puede bloquearse |
| Diseño final no aprobado | No se puede construir |
| Forms no definidos | No se puede capturar leads |
| Analytics no definidos | Se pierde datos desde el día 1 |
| Legal no revisado | Riesgo de lanzamiento |
| QA incompleto | Incidencias post-lanzamiento |

# 7. Gestión de cambios

Para que el lanzamiento no se retrasa:

## Antes de D-20

Se permiten cambios importantes:

- Estructura.
- Mensaje.
- CTA.
- Sections.
- Pricing.
- Propuesta de valor.

## Entre D-20 y D-12

Se permiten cambios menores:

- Copy.
- Diseño.
- Prioridad de secciones.
- Assets.

## Después de D-12

Solo se aceptan cambios críticos:

- Legal.
- Seguridad.
- Formulario.
- Error.
- Copy incorrecto.
- CTA no funcionando.
- Rendimiento crítico.

Todo lo demás pasa a una segunda iteración post-lanzamiento.
