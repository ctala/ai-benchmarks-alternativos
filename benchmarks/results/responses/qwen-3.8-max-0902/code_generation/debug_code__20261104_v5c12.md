## Respuesta completa

Los 3 bugs principales son estos:

## Bug 1: División por cero si no hay órdenes `pending`

En esta línea:

```python
average = total / len(processed)
```

Si ninguna orden tiene `status == 'pending'`, entonces `processed` será una lista vacía y `len(processed)` será `0`.

Eso provoca:

```python
ZeroDivisionError: division by zero
```

### Corrección

Calcular el promedio solo si hay órdenes procesadas:

```python
average = total / count if count > 0 else 0
```

---

## Bug 2: Se muta el diccionario original

Aquí se está modificando directamente el diccionario `order` que viene en la lista `orders`:

```python
order['final_price'] = final_price
order['status'] = 'processed'
```

Eso altera los datos originales recibidos por la función.

Por ejemplo:

```python
orders = [{'status': 'pending', 'total': 200}]
process_orders(orders)
print(orders)
```

Después de ejecutar la función, `orders` ya no contiene los datos originales, sino que fue modificado.

### Corrección

Crear una copia del diccionario antes de modificarlo:

```python
processed_order = {**order, 'final_price': final_price, 'status': 'processed'}
```

Así la función no altera el diccionario original.

## Bug 3: `count` debería ser `len(processed)`, no `len(orders)`

En el retorno original:

```python
'count': len(orders)
```

Se está devolviendo la cantidad total de órdenes recibidas, no la cantidad de órdenes realmente procesadas.

Si llegan 5 órdenes pero solo 2 están `pending`, el resultado diría incorrectamente:

```python

```

Cuando debería decir:

```python
'count': 2
```

### Corrección

Usar:

```python
'count': len(processed)
```

def process_orders(orders):
