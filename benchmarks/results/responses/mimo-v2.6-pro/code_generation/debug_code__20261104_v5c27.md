# Bugs identificados y corrección

## Bug 1: División por cero

Si ninguna orden tiene `status == 'pending'`, la lista `processed` queda vacía. Esto provoca:

```python
average = total / len(processed)  # ZeroDivisionError: division by zero
```

**Corrección:** Validar que `processed` no esté vacío antes de dividir.

---

## Bug 2: Mutación del diccionario original

```python
order['final_price'] = final_price
order['status'] = 'processed'
```

Esto **modifica directamente** los diccionarios que vinieron en `orders`. El caller pierde los datos originales (`status: 'pending'`, sin `final_price`). En Python los diccionarios se pasan **por referencia**, no por copia.

**Corrección:** Trabajar sobre una copia superficial de cada orden con `copy()`.

---

## Bug 3: `count` devuelve el total de órdenes, no las procesadas

```python
'count': len(orders)  # Incluye órdenes que NO se procesaron
```

El campo `count` dentro del contexto de "resultados procesados" debería reflejar cuántas órdenes efectivamente se procesaron.

**Corrección:** Usar `len(processed)`.

---

## Código corregido

```python
import copy

def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] == 'pending':
            # BUG 2 FIX: copia superficial para no mutar el original
            order_copy = copy.copy(order)

            discount = order['total'] * 0.1 if order['total'] > 100 else 0
            final_price = order['total'] - discount

            order_copy['final_price'] = final_price
            order_copy['status'] = 'processed'

            total += final_price
            processed.append(order_copy)

    # BUG 1 FIX: evitar división por cero
    average = total / len(processed) if processed else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)  # BUG 3 FIX: contar solo las procesadas
    }
```
