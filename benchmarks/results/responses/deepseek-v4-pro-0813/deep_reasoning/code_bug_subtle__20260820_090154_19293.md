## Respuesta completa

El bug sutil está en el caso en que la **MAD (mediana de las desviaciones absolutas) es 0**. En ese caso el código no revienta, pero devuelve un promedio incorrecto.

Esto ocurre cuando **más de la mitad de los datos son exactamente iguales a la mediana**. Por ejemplo:

```python
data = [1, 1, 1, 2]
```

Paso a paso:

```python
median = 1
desviaciones = [0, 0, 0, 1]

mad = find_median([0, 0, 0, 1])
# n = 4, par -> promedio de los dos del medio: (0 + 0) / 2 = 0

threshold = 3 * 0 = 0

filtered = [x for x in data if abs(x - 1) <= 0]
# filtered = [1, 1, 1]
```

El valor `2` se descarta aunque no sea un valor atípico real, solo porque la MAD es 0. Entonces el promedio final se calcula solo con los valores repetidos:

```python
return sum([1, 1, 1]) / 3  # 1.0
```

La causa es que `threshold = 3 * mad` se convierte en `0` cuando `mad == 0`, y la condición `abs(x - median) <= threshold` solo permite elementos idénticos a la mediana.

En resumen, falla silenciosamente cuando hay una **mayoría estricta de datos iguales a la mediana**, algo común con datos discretos, redondeados o con valores repetidos.

Un caso aparte más obvio: si `data` está vacía, `sum(data) / len(data)` lanza `ZeroDivisionError`.
