## Bugs identificados

**1. División por cero**

Si `orders` está vacía o ninguna orden tiene status `'pending'`, `processed` queda vacía y `total / len(processed)` lanza `ZeroDivisionError`.

**2. Mutación del diccionario original**

`order['final_price'] = ...` y `order['status'] = 'processed'` modifican los diccionarios que pasó el llamador. Esto causa efectos secundarios: los datos originales cambian sin que el llamador lo espere. Además, la función deja de ser idempotente: si la llamas dos veces con la misma lista, la segunda vez no procesa nada porque ya ninguna orden está en `'pending'`.

**3. `count` incorrecto**

`len(orders)` cuenta todas las órdenes recibidas, no las procesadas. Esto es inconsistente con `total` y `average`, que solo consideran las procesadas.

## Versión corregida

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] == 'pending':
            discount = order['total'] * 0.1 if order['total'] > 100 else 0
            final_price = order['total'] - discount

            # Bug 2: se crea una copia en lugar de mutar el original
            processed_order = {
                **order,
                'final_price': final_price,
                'status': 'processed',
            }

            total += final_price
            processed.append(processed_order)

    count = len(processed)

    # Bug 1: se evita la división por cero
    average = total / count if count > 0 else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': count,  # Bug 3: cuenta solo las procesadas
    }
```

## Notas

- `{**order, ...}` hace una copia superficial. Aquí basta, porque solo se modifican claves de primer nivel. Si las órdenes tuvieran estructuras anidadas que luego se modifican, convendría usar `copy.deepcopy(order)`.
- Para `average` sin órdenes procesadas elegí `0`, pero `None` también es válido si quieres distinguir "promedio cero" de "no hay datos".
