# El éxito que no significa nada

Tu workflow aparece en verde, sin errores, y aun así no procesó ni un solo registro. En n8n, "success" significa que ningún nodo lanzó una excepción. No significa que el trabajo se haya hecho.

**Dónde se esconde el falso positivo:**

- **Ramas vacías.** Un IF que evalúa a `false` sin nada conectado en esa salida termina la ejecución sin error.
- **Filtros que devuelven cero items.** Todos los nodos siguientes simplemente no se ejecutan. La ejecución queda marcada como exitosa.
- **Loops sobre arrays vacíos.** Un Loop Over Items con cero entradas no falla: no hace nada.
- **"Continue On Fail" y "Always Output Data".** Tragan el error y pasan un item vacío o con `error` dentro del JSON. El siguiente nodo lo procesa como si fuera válido.
- **HTTP Request con respuesta 200 y cuerpo inesperado.** Una API que devuelve `{"error": "rate limit"}` o un array vacío con status 200 no dispara nada.
- **Expresiones que resuelven a `undefined`.** Un Set o un Code que referencia un campo mal escrito produce items con valores nulos sin quejarse.

**Cómo detectarlo:**

1. **Asserta el output esperado.** Un nodo IF al final que verifique `{{ $json.length }}` o el conteo de items, y que lance un Stop and Error si el mínimo no se cumple.
2. **Heartbeat de volumen.** Registra cuántos items procesa cada ejecución en una hoja o base de datos. Una alerta cuando el número cae a cero en un workflow que siempre debería tener datos te ahorra semanas de silencio.
3. **Valida la forma de la respuesta,** no solo el status code. Comprueba que el campo que necesitas exista antes de continuar.
4. **Usa un Error Trigger global** para capturar fallos que tus ramas silenciosas esconden.
5. **Revisa la duración.** Una ejecución que tarda 200 ms cuando normalmente tarda 4 s probablemente no hizo lo que creías.

El verde del dashboard solo te dice que nada explotó. Lo que importa es que hiciste lo que debías.
