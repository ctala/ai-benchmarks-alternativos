## Bugs identificados

### 1. División por cero
Si ninguna orden tiene `status == 'pending'`, `processed` queda vacío y `total / len(processed)` lanza `ZeroDivisionError`.

**Corrección:** calcular el promedio solo si hay órdenes procesadas. Devuelvo `None` en lugar de `0`, porque un promedio de 0 podría confundirse con un promedio real de 0.

### 2. Muta el diccionario original
`order['final_price']` y `order['status'] = 'processed'` modifican las órdenes que recibe la función. El llamador puede no esperar ese efecto secundario, y si vuelve a pasar la misma lista, las órdenes ya no están en `'pending'`.

**Corrección:** trabajar sobre una copia (`dict(order)`). Si las órdenes tuvieran valores anidados (listas o diccionarios), habría que usar `copy.deepcopy`.

### 3. `count` (depende de la intención)
Esto es ambiguo. `len(orders)` cuenta todas las órdenes recibidas, no las procesadas. Si `count` debe significar órdenes procesadas, el cambio es correcto. Para evitar ambigüedad, devuelvo ambos valores con nombres explícitos.

def process_orders(orders):
    processed = []
    total = 0.0

    for order in orders:
        if order['status'] != 'pending':
            continue

        new_order = dict(order)  # copia: no mutamos el original
        base = new_order['total']
        discount = base * 0.1 if base > 100 else 0
        final_price = base - discount

        new_order['final_price'] = final_price
        new_order['status'] = 'processed'
        total += final_price
        processed.append(new_order)

    average = total / len(processed) if processed else None

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed),        # órdenes procesadas
        'total_orders': len(orders),    # órdenes recibidas
    }
