## El bug: MAD = 0 colapsa el umbral y descarta datos válidos

El fallo ocurre cuando **más de la mitad de los valores son idénticos al mediano**. En ese caso:

1. Las desviaciones absolutas `|x - median|` tienen más de la mitad de sus valores iguales a `0`.
2. Entonces `mad = find_median(...)` es `0`.
3. `threshold = 3 * 0 = 0`.
4. El filtro `abs(x - median) <= 0` solo conserva los valores exactamente iguales a la mediana.

El resultado es que **todos los demás valores se descartan silenciosamente**, aunque no sean outliers. No hay excepción ni advertencia, solo un resultado incorrecto.

### Ejemplo concreto

```python
data = [1, 1, 1, 1, 2, 3, 4]
```

- `sorted_nums = [1, 1, 1, 1, 2, 3, 4]`, `n = 7`, `mid = 3`, `median = 1`
- Desviaciones: `[0, 0, 0, 0, 1, 2, 3]` → ordenadas, la mediana es `0`, así que `mad = 0`
- `threshold = 0`
- `filtered = [1, 1, 1, 1]`
- Resultado: `1.0`

El valor esperado, si los 2, 3 y 4 son datos legítimos, sería algo cercano a la media de todos los datos (≈1.857). La función devuelve `1.0` sin avisar.

### Por qué ocurre

El MAD mide la dispersión típica alrededor de la mediana. Cuando la mayoría de los datos son iguales, la dispersión típica es cero, y la regla `|x - mediana| <= 3·MAD` se vuelve una comparación de igualdad exacta. La fórmula funciona bien para distribuciones con dispersión, pero no tiene un mecanismo de respaldo cuando MAD = 0.

### Otro caso de borde (menor)

Si `data` es una lista vacía, la rama `len(data) < 3` ejecuta `sum(data) / len(data)`, que lanza `ZeroDivisionError`. Es un fallo distinto, pero también depende de datos específicos.

### Posibles correcciones

- Si MAD = 0, no filtrar, o usar un umbral de respaldo, por ejemplo una fracción de la media absoluta de desviaciones (`mean(|x - median|)`) o la desviación estándar.
- Validar `if not data: raise ValueError(...)` al inicio.
- Considerar la constante de escala `1.4826 · MAD` si se quiere que el umbral sea comparable con una desviación estándar en datos normales.
