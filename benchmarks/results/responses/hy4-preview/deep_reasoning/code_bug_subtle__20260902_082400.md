## Respuesta completa

El bug “silencioso” está aquí:

```python
threshold = 3 * mad
filtered = [x for x in data if abs(x - median) <= threshold]
```

Falla cuando `mad == 0`.

### Cuándo ocurre exactamente

Sea:

```python
deviations = [abs(x - median) for x in data]
```

Como todas las desviaciones son `>= 0`, `find_median(deviations) == 0` ocurre cuando más de la mitad de los elementos son exactamente iguales a la mediana.

Formalmente, para `n = len(data)`, `mad == 0` cuando al menos:

```python
n // 2 + 1
```

elementos son exactamente iguales a `median`.

### Por qué falla

Si `mad == 0`, entonces:

```python
threshold = 3 * 0  # 0
```

y el filtro se convierte en:

```python
filtered = [x for x in data if abs(x - median) <= 0]
```

Es decir, solo deja pasar valores exactamente iguales a la mediana. Todos los demás valores se eliminan, aunque estén muy cerca y no sean outliers reales.

### Ejemplo

```python
data = [1, 1, 1, 2, 3]
```

Cálculo:

```python
median = 1
deviations = [0, 0, 0, 1, 2]
mad = 0
threshold = 0
filtered = [1, 1, 1]
return 1.0
```

Aquí elimina `2` y `3`, aunque `2` difícilmente debería considerarse outlier.

También pasa con números decimales:

```python
data = [10, 10, 10, 10.1, 10.2]
```

Devuelve `10.0`, descartando `10.1` y `10.2`.

### Caso aparte

Si `data` puede ser vacío, hay otro bug distinto:

```python
remove_outliers_and_average([])
```

Entra en:

```python
if len(data) < 3:
    return sum(data) / len(data)
```

y hace:

```python
0 / 0
```

lanzando `ZeroDivisionError`.

La solución conceptual sería tratar explícitamente `data == []` y también manejar el caso degenerado `mad == 0`.
