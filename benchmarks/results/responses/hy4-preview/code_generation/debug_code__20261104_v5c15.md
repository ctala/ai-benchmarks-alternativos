## Bugs

### 1. División por cero

```python
average = total / len(processed)
```

Si no hay órdenes con estado `'pending'`, entonces `processed` queda vacío y `len(processed)` es `0`, provocando:

```python
ZeroDivisionError
```

**Corrección:** calcular el promedio solo si hay órdenes procesadas.

---

### 2. Muta el diccionario original

```python
order['final_price'] = final_price
order['status'] = 'processed'
processed.append(order)
```

Aquí estás modificando directamente los diccionarios que vienen en `orders`. Además, `processed.append(order)` guarda una referencia al mismo objeto, no una copia.

**Corrección:** copiar la orden antes de modificarla.

---

### 3. `count` incorrecto

```python
'count': len(orders)
```

`len(orders)` cuenta todas las órdenes recibidas, no solo las procesadas.

**Corrección:** usar `len(processed)`.

---

## Versión corregida

```python
from copy import deepcopy

def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] == 'pending':
            subtotal = order['total']
            discount = subtotal * 0.1 if subtotal > 100 else 0
            final_price = subtotal - discount

            # Copiamos la orden para no mutar la original
            processed_order = deepcopy(order)
            processed_order['final_price'] = final_price
            processed_order['status'] = 'processed'

            processed.append(processed_order)
            total += final_price

    count = len(processed)
    average = total / count if count > 0 else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': count
    }
```

Si sabes que las órdenes son diccionarios simples, sin objetos anidados, puedes usar una copia superficial:

```python
processed_order = order.copy()
```

Pero si dentro de `order` hay listas, diccionarios u otros objetos mutables, `deepcopy` es más seguro.
