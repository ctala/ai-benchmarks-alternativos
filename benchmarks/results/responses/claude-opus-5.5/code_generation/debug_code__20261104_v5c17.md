# Análisis de bugs

## Bug 1: División por cero

```python
average = total / len(processed)
```

Si ninguna orden tiene `status == 'pending'`, o si `orders` está vacía, `processed` queda vacía y se lanza `ZeroDivisionError`.

```python
process_orders([])                                   # ZeroDivisionError
process_orders([{'status': 'shipped', 'total': 50}]) # ZeroDivisionError
```

**Solución:** comprobar que haya elementos antes de dividir.

```python
average = total / len(processed) if processed else 0
```

## Bug 2: Mutación del diccionario original

```python
order['final_price'] = final_price
order['status'] = 'processed'
```

`order` es una referencia al mismo diccionario que está en la lista del llamador, no una copia. La función modifica sus datos sin avisar:

```python
orders = [{'status': 'pending', 'total': 200}]
process_orders(orders)
print(orders)  # [{'status': 'processed', 'total': 200, 'final_price': 180.0}]
```

Esto causa varios problemas:
- **Efecto secundario oculto:** el llamador no espera que sus datos cambien.
- **No es idempotente:** si se llama dos veces con la misma lista, la segunda vez no procesa nada, porque las órdenes ya no están en `'pending'`.
- **Aliasing:** los objetos en `result['processed']` son los mismos que en `orders`, así que modificar uno modifica el otro.

**Solución:** crear un diccionario nuevo para cada orden procesada.

```python
new_order = {**order, 'final_price': final_price, 'status': 'processed'}
```

## Bug 3: `count` incorrecto

```python
'count': len(orders)
```

Cuenta todas las órdenes recibidas, incluidas las que no se procesaron. Eso es inconsistente con `total` y `average`, que solo consideran las procesadas:

```python
orders = [
    {'status': 'pending', 'total': 50},
    {'status': 'shipped', 'total': 80},
    {'status': 'cancelled', 'total': 30},
]
# Resultado: count = 3, pero solo se procesó 1 orden
# Además, average != total / count, lo que confunde a quien use el resultado
```

**Solución:** usar `len(processed)`.

# Versión corregida

```python
DISCOUNT_THRESHOLD = 100
DISCOUNT_RATE = 0.1


def process_orders(orders):
    """
    Procesa las órdenes con estado 'pending' aplicando un descuento
    del 10% a las que superan el umbral.

    No modifica la lista ni los diccionarios de entrada.
    """
    total = 0
    processed = []

    for order in orders:
        if order.get('status') != 'pending':
            continue

        order_total = order['total']
        discount = order_total * DISCOUNT_RATE if order_total > DISCOUNT_THRESHOLD else 0
        final_price = order_total - discount

        # Bug 2: crear un diccionario nuevo en lugar de mutar el original
        processed_order = {
            **order,
            'final_price': final_price,
            'status': 'processed',
        }

        total += final_price
        processed.append(processed_order)

    count = len(processed)
    # Bug 1: evitar la división por cero
    average = total / count if count else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': count,  # Bug 3: contar solo las órdenes procesadas
    }
```

# Mejoras adicionales (no son bugs estrictos, pero conviene considerarlas)

1. **Copia superficial vs. profunda:** `{**order}` es una copia superficial. Si una orden contiene estructuras anidadas (por ejemplo, una lista `items`), estas se siguen compartiendo con el original. Aquí no es un problema porque solo se modifican claves de primer nivel. Si más adelante se modifican datos anidados, conviene usar `copy.deepcopy(order)`.

2. **Precisión con dinero:** `float` acumula errores de redondeo (`0.1 + 0.2 != 0.3`). Para cálculos monetarios es preferible usar `decimal.Decimal`, o trabajar en centavos con enteros.

3. **Claves faltantes:** `order['total']` lanza `KeyError` si falta la clave. Según el caso, puede convenir validar la entrada o lanzar un error más descriptivo.

4. **Umbral ambiguo:** `> 100` excluye exactamente 100. Conviene confirmar con los requisitos si debería ser `>= 100`.

5. **Tipo de `average`:** cuando no hay órdenes, la función devuelve `0`. Otra opción es devolver `None` para distinguir "no hay datos" de "el promedio es cero". Depende de lo que espere quien consume el resultado.
