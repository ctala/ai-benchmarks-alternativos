# Top 10 clientes por revenue (últimos 6 meses)

Esta versión está escrita para **PostgreSQL**:

```sql
WITH completed_orders AS (
    -- Órdenes completadas de los últimos 6 meses
    SELECT
        o.id,
        o.customer_id,
        o.total
    FROM orders o
    WHERE o.status = 'completed'
      AND o.created_at >= CURRENT_DATE - INTERVAL '6 months'
),

customer_stats AS (
    -- Métricas por cliente (sin joins a items para evitar duplicar totales)
    SELECT
        customer_id,
        COUNT(*)    AS total_orders,
        SUM(total)  AS total_revenue,
        AVG(total)  AS avg_order_value
    FROM completed_orders
    GROUP BY customer_id
    HAVING COUNT(*) >= 3
),

category_ranking AS (
    -- Ranking de categorías por cliente según unidades compradas
    SELECT
        co.customer_id,
        p.category,
        ROW_NUMBER() OVER (
            PARTITION BY co.customer_id
            ORDER BY SUM(oi.quantity) DESC,                   -- 1º: más unidades
                     SUM(oi.quantity * oi.unit_price) DESC,   -- desempate: más gasto
                     p.category                               -- desempate final determinista
        ) AS rn
    FROM completed_orders co
    JOIN order_items oi ON oi.order_id = co.id
    JOIN products p     ON p.id = oi.product_id
    WHERE co.customer_id IN (SELECT customer_id FROM customer_stats)
    GROUP BY co.customer_id, p.category
)

SELECT
    c.name                          AS nombre,
    c.email,
    c.country                       AS pais,
    cs.total_orders,
    ROUND(cs.total_revenue, 2)      AS total_revenue,
    ROUND(cs.avg_order_value, 2)    AS avg_order_value,
    cr.category                     AS categoria_mas_comprada
FROM customer_stats cs
JOIN customers c
       ON c.id = cs.customer_id
LEFT JOIN category_ranking cr
       ON cr.customer_id = cs.customer_id
      AND cr.rn = 1
ORDER BY cs.total_revenue DESC
LIMIT 10;
```

## Decisiones de diseño

1. **Se evita el "fan-out".** Si se unen `orders` con `order_items` antes de agregar, cada orden se repite una vez por cada ítem y `SUM(o.total)` sale inflado. Por eso las métricas de órdenes y la categoría se calculan en CTEs separados.

2. **Criterio de "categoría más comprada":** se usa la categoría con más **unidades** compradas. Si prefieres la categoría con más **gasto**, invierte el orden de los dos primeros criterios del `ORDER BY` en el `ROW_NUMBER()`.

3. **Empates:** el `ROW_NUMBER()` con desempates garantiza una sola categoría por cliente y un resultado determinista.

4. **`LEFT JOIN` en categorías:** si un cliente tuviera órdenes sin ítems (datos inconsistentes), sigue apareciendo en el resultado con categoría `NULL`.

5. **El mínimo de 3 órdenes se aplica dentro de los últimos 6 meses.** Si querías "al menos 3 órdenes completadas en toda su historia", hay que mover esa condición a un CTE aparte, sin filtro de fecha.
