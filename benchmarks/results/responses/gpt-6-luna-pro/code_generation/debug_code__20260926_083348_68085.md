## Respuesta completa

Los tres bugs son:

1. **División por cero:** si no hay órdenes pendientes, `processed` queda vacío y `total / len(processed)` falla. Se puede devolver `0` como promedio cuando no se procesó ninguna orden.
2. **Modificación de los datos originales:** asignar valores a `order` cambia el diccionario recibido. Hay que trabajar con una copia.
3. **Conteo incorrecto:** `count` debe reflejar las órdenes procesadas, no todas las órdenes recibidas.

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] == 'pending':
            processed_order = order.copy()

            discount = (
                processed_order['total'] * 0.1
                if processed_order['total'] > 100
                else 0
            )
            final_price = processed_order['total'] - discount

            processed_order['final_price'] = final_price
            processed_order['status'] = 'processed'

            total += final_price
            processed.append(processed_order)

    count = len(processed)
    average = total / count if count else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': count,
    }
```

`order.copy()` crea una copia superficial, suficiente aquí porque solo se modifican valores del propio diccionario. Si se modificaran objetos anidados, haría falta una copia profunda.
