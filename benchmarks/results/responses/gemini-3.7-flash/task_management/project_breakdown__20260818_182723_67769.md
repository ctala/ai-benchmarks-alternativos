## Entrada exacta (lo que recibió el modelo)

**user:**

Necesito lanzar una landing page para un nuevo producto SaaS de gestion de inventario. El lanzamiento es en 4 semanas. El equipo tiene 1 disenador, 2 developers y 1 copywriter. Desglosa el proyecto en fases, tareas, dependencias, responsables y un timeline realista.


## Respuesta completa

Para lanzar una landing page de alta conversión en 4 semanas con este equipo, la clave es un enfoque **"Content-First"** (el contenido dicta el diseño, no al revés) y el trabajo en paralelo de los desarrolladores.

A continuación tienes el plan de proyecto detallado, estructurado para evitar cuellos de botella.

---

### **1. Roles y Responsabilidades (RACI Simplificado)**
*   **Copywriter (CW):** Propuesta de valor, narrativa de venta, microcopy, SEO on-page y correos transaccionales.
*   **Diseñador UX/UI (DES):** Wireframes, UI Kit, diseño final en Figma, prototipo interactivo y assets gráficos.
*   **Developer 1 - Frontend Lead (DEV 1):** Maquetación responsive, animaciones, accesibilidad y performance.
*   **Developer 2 - Integraciones/DevOps (DEV 2):** Setup de entorno, CI/CD, integración de formularios con CRM/Email, analítica y SEO técnico.

---

### **2. Cronograma Semana a Semana (Timeline de 4 Semanas)**

```
Leyenda: [CW] Copy | [DES] Diseñador | [DEV1] Frontend | [DEV2] Backend/Integraciones
```

#### **SEMANA 1: Estrategia, Copywriting y Wireframes**
*Objetivo: Tener la estructura y el contenido 100% aprobados.*

*   **Día 1-2: Kickoff y Alineación**
    *   Definir propuesta única de valor (UVP), ICP (perfil de cliente ideal: ej. eCommerce, retail) y objetivo principal (¿Registro a beta, demo o compra directa?). *(Todo el equipo)*
    *   Benchmark de competidores (Sortly, Katana, Zoho Inventory). *(CW, DES)*
*   **Día 3-4: Copy v1 & Wireframes Low-Fi**
    *   Redacción de todas las secciones: Hero, Dolor/Solución, Features clave, Prueba social, Pricing/Waitlist, FAQs. `[CW]`
    *   Estructura visual básica / Wireframes en baja fidelidad. `[DES]`
*   **Día 5: Revisión y Aprobación de Contenido**
    *   Validar wireframe + copy integrado. **Hito crítico: Congelar textos para no frenar diseño.** *(Todo el equipo)*

---

#### **SEMANA 2: UI Design, Assets y Setup Técnico**
*Objetivo: Diseño final aprobado y entorno de desarrollo listo.*

*   **Día 6-8: Diseño UI High-Fidelity & Setup Dev**
    *   Diseño visual final en Figma (Desktop y Mobile) con UI Kit (colores, tipografías, componentes). `[DES]`
    *   Creación de mockups del software de inventario (dashboards, alertas de stock, escaneo de códigos). `[DES]`
    *   Setup del proyecto (Next.js/Astro/Tailwind recomendado), repositorio en GitHub, pipeline de despliegue en Vercel/Netlify. `[DEV 1]`
    *   Configuración de dominio, DNS, SSL y entorno de staging. `[DEV 2]`
*   **Día 9-10: Handoff de Diseño y Microcopy**
    *   Revisión final de UI con el equipo. `[DES, DEV 1, DEV 2]`
    *   Exportación de assets optimizados (SVG, WebP). `[DES]`
    *   Redacción de emails de confirmación y estados de error/éxito de formularios. `[CW]`

---

#### **SEMANA 3: Desarrollo Frontend e Integraciones**
*Objetivo: Landing page 100% funcional en entorno de staging.*

*   **Día 11-13: Maquetación y Lógica**
    *   **DEV 1 (UI/Frontend):** Maquetación pixel-perfect de secciones (Hero, Features, Pricing interactivo, FAQs acordeón).
    *   **DEV 2 (Backend/Integraciones):**
        *   Integración del formulario con CRM / Email Marketing (HubSpot, Mailchimp, Loops, etc.).
        *   Configuración de base de datos para leads/early adopters si aplica.
        *   Creación de OpenGraph tags y metadatos dinámicos.
*   **Día 14-15: Responsive, Animaciones y Micro-interacciones**
    *   Ajuste mobile/tablet exhaustivo. `[DEV 1]`
    *   Animaciones sutiles (Framer Motion / CSS) para modernidad SaaS. `[DEV 1]`
    *   Implementación de Webhooks y validación de formularios (anti-spam / Captcha / validación de email corporativo). `[DEV 2]`

---

#### **SEMANA 4: QA, Analítica, Optimización y Lanzamiento**
*Objetivo: Cero errores, tracking perfecto y salida a producción.*

*   **Día 16-17: Analítica, SEO y Tracking**
    *   Configuración de Google Tag Manager, GA4, Meta Pixel y Hotjar/Clarity. `[DEV 2]`
    *   Definición de eventos de conversión (Click en CTA, envío de formulario, scroll depth). `[CW, DEV 2]`
    *   Revisión de textos legales (Términos, Privacidad, Banner de Cookies GDPR). `[CW, DEV 2]`
*   **Día 18-19: QA (Quality Assurance) y Testing**
    *   Cross-browser testing (Chrome, Safari, Firefox, Edge) y multidispositivo (iOS, Android). `[DES, DEV 1]`
    *   Prueba de estrés de formularios (asegurar que el lead entra al CRM y recibe el email). `[DEV 2, CW]`
    *   Auditoría de performance en Google PageSpeed / Lighthouse (Score > 90 requerido). `[DEV 1, DEV 2]`
*   **Día 20: Go-Live (Lanzamiento) 🚀**
    *   Pase a producción en el dominio principal (`www.tusaas.com`). `[DEV 2]`
    *   Smoke testing en vivo (probar flujo de captación en caliente). *(Todo el equipo)*
    *   Monitoreo de tráfico y errores en consola (Sentry / Vercel Logs). `[DEV 1, DEV 2]`

### **3. Matriz de Dependencias Críticas**

| Tarea Bloqueada | Depende de | Responsable de desbloquear |
| :--- | :--- | :--- |

| **Pase a Producción** | QA aprobado y Analítica verificada | Todo el equipo |

---

### **4. Recomendación de Stack Tecnológico (Optimizado para Velocidad y SEO)**

*   **Frontend:** Astro o Next.js + Tailwind CSS (Carga ultrarrápida, excelente para SEO).
*   **Hosting/CI-CD:** Vercel o Netlify (Despliegues automáticos en staging para revisión continua).
*   **Forms & CRM:** Formspree / Resend + HubSpot / Supabase.
*   **Analítica:** Google Tag Manager + GA4 + PostHog o Microsoft Clarity (Mapas de calor gratuitos).
*   **Diseño:** Figma.

---

### **5. Factores de Riesgo y Plan de Contingencia**
1.  **Scope Creep (Aumento del alcance):** Limitar la página a un diseño *One-Page* + página de Políticas de Privacidad/Términos. Dejar blog o subpáginas de features para la Fase 2 post-lanzamiento.
2.  **Cuello de botella en el Copy:** Si el copy se retrasa en Semana 1, el diseñador debe trabajar en componentes base y UI Kit para no perder tiempo.
3.  **Fallas de integración de última hora:** Los DEV deben probar la API del CRM con datos *mock* desde la Semana 2.
