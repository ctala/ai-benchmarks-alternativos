# Análisis de Bugs

## Bug 1: División por cero

Si `orders` está vacía o ninguna orden tiene status `'pending'`, la lista `processed` queda vacía y esta línea explota:

```python
average = total / len(processed)  # ZeroDivisionError si len(processed) == 0
```

**Corrección:** validar antes de dividir:

```python
average = total / len(processed) if processed else 0
```

## Bug 2: Mutación del diccionario original

`order` es una **referencia** al mismo diccionario que existe en la lista del llamador. Estas líneas modifican el objeto original:

```python
order['final_price'] = final_price   # ¡Muta el dict original!
order['status'] = 'processed'        # ¡Muta el dict original!
```

Esto produce efectos secundarios peligrosos. Por ejemplo, si llamas la función dos veces con la misma lista, la segunda vez no procesará nada porque los status ya fueron cambiados:

```python

process_orders(orders)
print(orders[0]['status'])  # 'processed' ← el original fue modificado 😱
```

**Corrección:** trabajar sobre una copia:

```python
processed_order = order.copy()  # copia superficial es suficiente para dicts planos
```

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] == 'pending':
            discount = order['total'] * 0.1 if order['total'] > 100 else 0
            final_price = order['total'] - discount

            # Fix Bug 2: copiar en lugar de mutar el original
            processed_order = order.copy()
            processed_order['final_price'] = final_price
            processed_order['status'] = 'processed'

            total += final_price
            processed.append(processed_order)

    # Fix Bug 1: evitar división por cero
    average = total / len(processed) if processed else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)  # Fix Bug 3
    }
```
