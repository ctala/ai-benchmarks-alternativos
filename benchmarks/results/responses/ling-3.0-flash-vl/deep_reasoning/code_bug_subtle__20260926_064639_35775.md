## Respuesta completa

## El bug sutil: `MAD = 0` provoca que se eliminen valores que no son outliers

### ¿Cuándo falla?

El bug aparece cuando **al menos la mitad de los datos son iguales al valor mediano**. Esto hace que el MAD (Median Absolute Deviation) sea **0**, lo cual convierte el umbral (`3 * mad`) en **0**.

### Ejemplo concreto

```python
remove_outliers_and_average([10, 10, 10, 10, 11])
```

Paso a paso:

1. **Mediana** de `[10, 10, 10, 10, 11]` → `10`
2. **Desviaciones absolutas**: `[0, 0, 0, 0, 1]`
3. **MAD** = mediana de `[0, 0, 0, 0, 1]` → `0` (la mitad de los valores son 0)
4. **Umbral** = `3 * 0 = 0`
5. **Filtrado**: se queda solo con valores donde `|x - 10| <= 0`, es decir, solo los `10`. El `11` se elimina.
6. **Resultado**: `10.0`

El valor `11` **no es un outlier** (está a solo 1 unidad de la mediana), pero se elimina igualmente.

### ¿Por qué ocurre?

El problema es conceptual: cuando muchos datos comparten el mismo valor (más de la mitad), la mediana de las desviaciones absolutas siempre será 0. Con un umbral de 0, **cualquier valor que difiera de la mediana, por mínimo que sea, se considera un outlier**. Esto incluye valores perfectamente válidos como `10.1` o `11`.

Otro ejemplo:
```python
remove_outliers_and_average([1, 1, 1, 1, 100])
# Mediana = 1, MAD = 0, umbral = 0
# Filtrado: [1, 1, 1, 1] → El 100 se elimina (aceptable)
# Pero también: [1, 1, 1, 1, 1.5] → El 1.5 se elimina (¡INCORRECTO!)
```

### Solución

Se debería manejar el caso especial donde `mad == 0`, por ejemplo:
- Si `mad == 0`, devolver la media original (o la mediana) sin filtrar, ya que no hay dispersión para detectar outliers.
- O usar un umbral mínimo alternativo.

```python
if mad == 0:
    return sum(data) / len(data)  # No hay dispersión; no se pueden detectar outliers
```
