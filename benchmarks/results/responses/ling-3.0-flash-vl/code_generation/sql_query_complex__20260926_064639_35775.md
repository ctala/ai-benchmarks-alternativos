## Entrada exacta (lo que recibió el modelo)

**user:**

Tengo estas tablas:
- orders (id, customer_id, total, status, created_at)
- customers (id, name, email, country, created_at)
- order_items (id, order_id, product_id, quantity, unit_price)
- products (id, name, category, price)

Escribe una query SQL que muestre:
- Top 10 clientes por revenue total en los ultimos 6 meses
- Con columnas: nombre, email, pais, total_orders, total_revenue, avg_order_value, categoria_mas_comprada
- Ordena por total_revenue DESC
- Solo clientes con al menos 3 ordenes completadas (status = 'completed')


## Respuesta completa

```sql
WITH completed_orders AS (
    -- Filtrar órdenes completadas en los últimos 6 meses
    SELECT 
        o.id AS order_id,
        o.customer_id,
        o.total
    FROM orders o
    WHERE o.status = 'completed'
      AND o.created_at >= CURRENT_DATE - INTERVAL '6 months'
),

customer_summary AS (
    -- Resumen por cliente: órdenes, revenue y promedio
    SELECT 
        c.id   AS customer_id,
        c.name,
        c.email,
        c.country,
        COUNT(co.order_id)  AS total_orders,
        SUM(co.total)       AS total_revenue,
        AVG(co.total)       AS avg_order_value
    FROM customers c
    JOIN completed_orders co ON co.customer_id = c.id
    GROUP BY c.id, c.name, c.email, c.country
    HAVING COUNT(co.order_id) >= 3
),

category_ranked AS (
    -- Ranking de categorías por cliente (por revenue de categoría)
    SELECT 
        co.customer_id,
        p.category,
        SUM(oi.quantity * oi.unit_price) AS category_revenue,
        ROW_NUMBER() OVER (
            PARTITION BY co.customer_id 
            ORDER BY SUM(oi.quantity * oi.unit_price) DESC
        ) AS rn
    FROM completed_orders co
    JOIN order_items oi ON oi.order_id = co.order_id
    JOIN products p     ON p.id = oi.product_id
    GROUP BY co.customer_id, p.category
)

-- Resultado final: Top 10 clientes
SELECT 
    cs.name                AS nombre,
    cs.email,
    cs.country             AS pais,
    cs.total_orders,
    cs.total_revenue,
    ROUND(cs.avg_order_value, 2)  AS avg_order_value,
    cr.category            AS categoria_mas_comprada
FROM customer_summary cs
JOIN category_ranked cr 
    ON  cr.customer_id = cs.customer_id 
    AND cr.rn = 1                       -- solo la categoría más comprada
ORDER BY cs.total_revenue DESC
LIMIT 10;
```

### Explicación paso a paso

| CTE | Propósito |
|---|---|
| **`completed_orders`** | Filtra las órdenes con `status = 'completed'` y `created_at` dentro de los últimos 6 meses. Se usa como base para todo el análisis. |
| **`customer_summary`** | Agrupa por cliente y calcula `total_orders`, `total_revenue` (suma de `orders.total`) y `avg_order_value`. Filtra con `HAVING COUNT(...) >= 3` para quedarse solo con clientes que tengan al menos 3 órdenes completadas. |
| **`category_ranked`** | Une `order_items` con `products` para calcular el revenue por categoría (`SUM(quantity * unit_price)`) de cada cliente. Usa `ROW_NUMBER()` para rankear las categorías; la fila con `rn = 1` es la más comprada. |
| **Query final** | Une `customer_summary` con `category_ranked` (solo `rn = 1`) y ordena por `total_revenue DESC`, limitando a 10 filas. |

### Notas sobre compatibilidad de fechas

La expresión `CURRENT_DATE - INTERVAL '6 months'` es estándar **PostgreSQL**. Para otros motores:

| Motor | Sintaxis alternativa |
|---|---|
| **MySQL** | `DATE_SUB(CURDATE(), INTERVAL 6 MONTH)` |
| **SQL Server** | `DATEADD(MONTH, -6, GETDATE())` |
| **SQLite** | `DATE('now', '-6 months')` |

### Nota sobre `total_revenue`

Se usa `SUM(co.total)` directamente desde la tabla `orders`. Si prefieres calcular el revenue desde los ítems (puede diferir si `orders.total` no se sincroniza), reemplaza en `customer_summary`:

```sql
SUM((SELECT SUM(oi2.quantity * oi2.unit_price) 
     FROM order_items oi2 
     WHERE oi2.order_id = co.order_id)) AS total_revenue
```

O bien, haz el join con `order_items` directamente en `customer_summary` y usa `SUM(oi.quantity * oi.unit_price)`, teniendo cuidado de no duplicar al agregar por cliente (puedes usar una subconsulta intermedia).
