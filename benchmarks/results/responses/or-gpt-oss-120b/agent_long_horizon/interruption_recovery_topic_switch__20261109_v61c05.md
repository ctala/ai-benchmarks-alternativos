1. **Crear un repositorio Git privado** (GitHub, GitLab, Bitbucket) llamado `blog-posts`.  
   - Dentro, estructura de carpetas:  

     ```
     /_posts/
        2024-05-01-5-habitos-productividad.md
        2024-05-08-automatiza-tu-dia.md
     /_templates/
        blog-post-template.md
     /_assets/
        images/
        PDFs/
     ```

2. **Instalar plugins esenciales**  

   - **Obsidian Git** (auto‑push/pull cada X minutos).  
   - **Templater** (para plantillas con front‑matter).  
   - **Advanced Tables** (para tablas Markdown).  
   - **Obsidian Publish** (opcional, si quieres un sitio estático).  

3. **Plantilla de blog post (Templater)** – guarda en `_templates/blog-post-template.md`

   ```markdown
   ---
   title: {{title}}
   date: {{date:YYYY-MM-DD}}
   slug: {{slug}}
   tags: [{{tags}}]
   description: "{{excerpt}}"
   author: "Tu Nombre"
   editor: "{{editor}}"
   version: 1
   ---
   # {{title}}

   > **Brief del editor**  
   {{cursor}}

   ## Introducción
   ...

   ## Sub‑título 1
   ...

   ## Conclusión
   ...

   ## Fuentes
   - 

   ## Checklist SEO
   - [ ] Palabra clave principal en H1 y meta‑description
   - [ ] > 1200 palabras
   - [ ] 2‑3 enlaces internos
   - [ ] 1‑2 enlaces externos de autoridad
   - [ ] Imagen ALT text
   ```

4. **Proceso de redacción y revisión**

   1. **Tú** creas una nueva nota usando la plantilla (`Ctrl+P → Templater: Insert Template → blog‑post‑template`).  
   2. Redactas el borrador, guardas, y haces `git add . && git commit -m "draft: 5‑habitos‑productividad v1"` → *push* automático.  
   3. **Editor** clona el repo (o simplemente abre la carpeta en su Obsidian) y abre la nota.  
   4. **Revisión**:  
      - Usa **comentarios en línea** con el plugin **Obsidian Inline Comments** (gratuito) o simplemente escribe en bloques de **«> [!NOTE] Comentario del editor»**.  
      - Incrementa `version:` en el front‑matter y escribe `git commit -m "review: v2 – correcciones de estilo"` → push.  
   5. **Tú** haces los cambios, aumentas la versión y vuelves a *push*.  
   6. Cuando todo está OK, cambia el estado en el front‑matter a `status: approved` (puedes añadir esa clave) y haz el último commit.  

5. **Publicación automática (opcional)**  

   - **GitHub Actions** → al detectar `status: approved` en el front‑matter, ejecuta un script que convierta el Markdown a HTML (usando `pandoc` o `jekyll`) y lo despliegue en **Netlify** o **Vercel**.  
   - **WordPress** → usa el plugin **WP‑GitHub‑Sync** o **WP‑CLI** para importar el Markdown como borrador.  

6. **Comunicación**  

   - **Slack / Discord**: crea un canal #blog‑review. Cada vez que haces `git push`, el bot (por ejemplo **GitHub Slack Integration**) envía una notificación con el link al archivo en GitHub.  
   - **Issue Tracker**: abre un *issue* por cada post; el editor comenta directamente allí y puedes cerrar cuando el post está aprobado.

   - **Images without ALT**  
   - **Internal links** (lista)  
6. Corrige los puntos rojos y vuelve a analizar hasta alcanzar **≥ 80**.  

> **Truco:** Puedes añadir una línea al final de la plantilla: `<!-- seo: {{seo_score}} -->` y usar **Dataview** para extraer ese valor y crear una tabla de todos los posts con su score.

## 6️⃣ Mini‑guía de automatización en **Notion + Zapier + RankMath**

1. **Crea una base de datos** “Blog Posts” con columnas: `Title`, `Slug`, `Meta Description`, `Focus Keyword`, `Status`, `Yoast Score`.  
2. **Zap #1 – Notion → WordPress (draft)**  
   - **Trigger:** New/Updated Database Item (filter `Status = Ready for SEO`).  
   - **Action:** WordPress → *Create Post* (pasar `title`, `slug`, `content` (exported Markdown), `meta_description`).  
   - **Action:** *Delay* 1 min (para que RankMath analice).  
3. **Zap #2 – WordPress → Notion (Score)**  
   - **Trigger:** New Post (or Updated Post) en WordPress.  
   - **Action:** *Webhooks → GET* a la **RankMath REST endpoint**: `https://your‑site.com/wp-json/rankmath/v1/seo?post_id={{ID}}`.  
   - **Action:** *Update Database Item* en Notion → escribe el valor del campo `seo_score` en la columna `Yoast Score`.  
4. **En Notion**, añade una vista de tabla filtrada por `Yoast Score < 80` para ver rápidamente los posts que requieren ajustes.  

> **Resultado:** El editor freelance solo necesita abrir la página del post en Notion, ver el score y corregir los ítems señalados (título, descripción, enlaces). Cuando sube el score, el post pasa automáticamente a la fase “Aprobado → Programado”.
