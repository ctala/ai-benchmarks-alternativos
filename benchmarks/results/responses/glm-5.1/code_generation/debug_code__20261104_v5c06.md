# Análisis de Bugs

## Bug 1: División por cero
```python
average = total / len(processed)
```
Si ninguna orden tiene `status == 'pending'`, la lista `processed` queda vacía y `len(processed)` es `0`, lanzando `ZeroDivisionError`.

## Bug 2: Mutación del diccionario original
```python
order['final_price'] = final_price
order['status'] = 'processed'
```
Se modifican directamente los diccionarios que el llamador pasó como argumento. Esto es un **efecto secundario indeseado**: el código que invoca `process_orders` verá sus ordenes modificadas (cambiando `status` a `'processed'` y añadiendo `final_price`), aunque probablemente no lo esperaba. Se debe crear una **copia** del diccionario.

## Bug 3: `count` incorrecto
```python
'count': len(orders)
```
Se reporta la cantidad total de órdenes recibidas, pero lo coherente con el resto del resultado es reportar cuántas órdenes fueron **procesadas** (es decir, `len(processed)`). De lo contrario, `count` no coincide con la longitud de `processed`.

# Versión corregida

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] == 'pending':
            discount = order['total'] * 0.1 if order['total'] > 100 else 0
            final_price = order['total'] - discount

            # Bug 2 fix: copiamos para no mutar el original
            new_order = dict(order)
            new_order['final_price'] = final_price
            new_order['status'] = 'processed'

            total += final_price
            processed.append(new_order)

    # Bug 1 fix: evitamos división por cero
    average = total / len(processed) if processed else 0

    # Bug 3 fix: contamos solo las procesadas
    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)
    }
```

### Notas adicionales
- `dict(order)` hace una copia **superficial**. Si los valores fueran listas/dict anidados que también se mutan, convendría usar `copy.deepcopy(order)`. Aquí, como solo añadimos/reescribimos claves de primer nivel, la copia superficial es suficiente.
- Se podría además validar la existencia de las claves `'status'` y `'total'` con `order.get('status')` / `order.get('total', 0)` para hacerlo más robusto frente a datos incompletos.
