# Análisis de bugs

## Bug 1: División por cero
```python
average = total / len(processed)
```
Si no hay órdenes pendientes (o la lista `orders` está vacía), `len(processed)` es `0` y lanza `ZeroDivisionError`.

## Bug 2: Mutación de los diccionarios originales
```python
order['final_price'] = final_price
order['status'] = 'processed'
```
Se modifican los diccionarios originales que el caller pasó como argumento. Esto es un **efecto secundario** peligroso: el código que llamó a la función verá sus datos alterados sin saberlo. Hay que crear copias.

## Bug 3: `count` incorrecto
```python
'count': len(orders)
```
Cuenta **todas** las órdenes, pero solo se procesaron las pendientes. Debería ser `len(processed)` para reflejar cuántas se procesaron realmente.

# Versión corregida

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order.get('status') == 'pending':
            discount = order['total'] * 0.1 if order['total'] > 100 else 0
            final_price = order['total'] - discount

            # Crear una copia para no mutar el original
            processed_order = {
                **order,                # copia de los campos originales
                'final_price': final_price,
                'status': 'processed'
            }
            total += final_price
            processed.append(processed_order)

    # Evitar división por cero
    average = total / len(processed) if processed else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)   # Bug 3 corregido
    }
```
