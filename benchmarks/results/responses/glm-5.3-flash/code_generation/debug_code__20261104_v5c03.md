# Bugs identificados

## Bug 1: División por cero

```python
average = total / len(processed)
```

Si la lista `orders` está vacía, o ninguna orden tiene `status == 'pending'`, entonces `processed` queda vacía y `len(processed)` es `0`, lanzando:

```
ZeroDivisionError: division by zero
```

**Corrección:** verificar que la lista no esté vacía antes de dividir.

## Bug 2: Muta los diccionarios originales

```python
order['final_price'] = final_price
order['status'] = 'processed'
```

Estas líneas modifican los diccionarios que el caller pasó como argumento. Esto es peligroso porque:

- El caller ve sus datos cambiados inesperadamente (la orden "pendiente" se convierte en "procesada" fuera de la función).
- Si se llama a la función dos veces con la misma lista, la segunda llamada **no procesa nada**, porque ninguna orden ya tiene `status == 'pending'`.

```python
orders = [{'status': 'pending', 'total': 200}]
process_orders(orders)
print(orders[0]['status'])  # 'processed' — ¡el original cambió!
```

**Corrección:** hacer una copia del diccionario antes de modificarlo.

## Bug 3: `count` incorrecto

```python
'count': len(orders)
```

El `count` del resultado debería reflejar cuántas órdenes **fueron procesadas**, no cuántas se recibieron. Con la versión actual, si pasas 10 órdenes y solo 3 están pendientes, el resultado dice `count: 10`, lo cual contradice `len(processed) == 3`.

**Corrección:** usar `len(processed)`.

# Versión corregida

```python
def process_orders(orders):
    total = 0
    processed = []
    for order in orders:
        if order['status'] == 'pending':
            discount = order['total'] * 0.1 if order['total'] > 100 else 0
            final_price = order['total'] - discount

            # Bug 2: copiar para no mutar el original
            processed_order = order.copy()
            processed_order['final_price'] = final_price
            processed_order['status'] = 'processed'

            total += final_price
            processed.append(processed_order)

    # Bug 1: evitar división por cero
    average = total / len(processed) if processed else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)  # Bug 3: contar solo las procesadas
    }
```

# Notas adicionales (no son bugs, pero conviene considerarlas)

1. **`average` cuando no hay órdenes:** devolver `0` es pragmático, pero semánticamente "el promedio de nada" es indefinido. Podrías devolver `None` y que el caller decida cómo manejarlo:

   ```python
   average = total / len(processed) if processed else None
   ```

2. **Copias superficiales:** `order.copy()` es una copia *shallow*. Si los diccionarios tuvieran estructuras anidadas (listas, otros dicts), esas siguen compartiéndose con el original. En ese caso usarías `copy.deepcopy(order)`.

3. **Flotantes para dinero:** usar `float` para precios puede acumular errores de redondeo (`0.1 + 0.2 != 0.3`). Para un sistema real, considera `decimal.Decimal` o trabajar en centavos con enteros.
