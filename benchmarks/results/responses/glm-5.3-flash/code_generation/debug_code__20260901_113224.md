# Análisis de los bugs

## Bug 1: `ZeroDivisionError` si no hay órdenes pendientes

```python
average = total / len(processed)
```

Si `orders` está vacía o ninguna orden tiene `status == 'pending'`, la lista `processed` queda vacía y `len(processed)` es `0`. Dividir entre cero lanza una excepción `ZeroDivisionError`.

**Corrección:** usar una expresión condicional que devuelva `0` (u otro valor sensible) cuando no hay elementos.

## Bug 2: Muta los diccionarios originales

```python
order['final_price'] = final_price
order['status'] = 'processed'
```

Los diccionarios en Python se pasan por referencia, así que estas líneas **modifican los datos del llamador**. Ejemplo del efecto secundario:

```python
orders = [{'status': 'pending', 'total': 150}]
result = process_orders(orders)
print(orders)
# [{'status': 'processed', 'total': 150, 'final_price': 135.0}]  ← ¡el original cambió!
```

Esto es especialmente peligroso si los mismos datos se usan después en otro lugar del programa (por ejemplo, reintentar el procesamiento ya no funcionaría porque el status cambió).

**Corrección:** crear una copia con `order.copy()` y modificar la copia. Una copia superficial basta porque solo agregamos/reemplazamos claves de primer nivel.

## Bug 3: `count` incorrecto

```python
'count': len(orders)
```

Cuenta **todas** las órdenes, incluidas las que ya estaban procesadas, canceladas, etc. Como la función reporta el resultado de *esta* ejecución, `count` debe reflejar cuántas se procesaron: `len(processed)`.

# Versión corregida

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order.get('status') == 'pending':
            # Bug 2: trabajar sobre una copia, no sobre el original
            processed_order = order.copy()

            order_total = processed_order['total']
            discount = order_total * 0.1 if order_total > 100 else 0

            processed_order['final_price'] = order_total - discount
            processed_order['status'] = 'processed'

            total += processed_order['final_price']
            processed.append(processed_order)

    # Bug 1: evitar división por cero
    average = total / len(processed) if processed else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,   # Bug 1: ahora seguro
        'count': len(processed)  # Bug 3: cuenta solo las procesadas
    }
```

# Observaciones adicionales (no bugs, pero recomendables)

- **`order.get('status')` en lugar de `order['status']`**: si alguna orden no tiene la clave `status`, el original lanzaría `KeyError`. Con `.get()` simplemente se omite la orden.
- **Precisión de flotantes**: para dinero, `0.1` en binario genera errores de redondeo (ej. `135.00000000000003`). Si necesitas exactitud, usa `decimal.Decimal` o redondea con `round(final_price, 2)`.
- **Copia superficial**: `order.copy()` es suficiente aquí, pero si las órdenes tuvieran estructuras anidadas mutables que también vas a modificar, necesitarías `copy.deepcopy(order)`.
