def find_median(numbers):

    threshold = 3 * mad

## Respuesta completa

## El bug: cuando la MAD es 0, el umbral colapsa a 0

El problema está en esta línea:

```python
threshold = 3 * mad
```

**Cuándo falla:** exactamente cuando la mediana se repite en más de la mitad de los datos (formalmente: cuando `mad == 0`, lo que ocurre si la mediana aparece ≥ `n // 2 + 1` veces).

**Por qué:** si la MAD es 0, entonces `threshold = 0`, y el filtro se convierte en:

```python
abs(x - median) <= 0   #  ⟺   x == median
```

Es decir, se descartan **todos** los valores que no sean idénticos a la mediana, sin importar qué tan cerca estén. La función degenera en "devolver la moda" en vez de promediar los datos sin outliers.

## Traza con datos concretos

```python
remove_outliers_and_average([10, 10, 10, 11, 12])
```

1. `median = 10`
2. Desviaciones: `[0, 0, 0, 1, 2]` → ordenadas `[0, 0, 0, 1, 2]` → `mad = 0`
3. `threshold = 3 * 0 = 0`
4. Filtro: solo sobreviven los `10` → `filtered = [10, 10, 10]`
5. Resultado: `10.0`

Aquí **no hay ningún outlier** — 11 y 12 son valores perfectamente normales — pero la función los elimina y devuelve 10 en vez de 10.6. Otro ejemplo con outlier real:

```python
remove_outliers_and_average([2, 2, 2, 3, 100])  # devuelve 2.0
# Lo razonable sería (2+2+2+3)/4 = 2.25 — el 3 no es outlier, pero lo tira igual
```

## Por qué es sutil y peligrosa

- **No lanza excepción**: devuelve un resultado plausible y silenciosamente incorrecto. Es peor que un crash.
- No depende de valores extremos: basta que haya un valor repetido en más del 50% de los datos (muy común con datos categóricos-cuantitativos, mediciones con resolución limitada, o datasets pequeños).
- No puedes detectarlo mirando el algoritmo "en general": el filtro MAD funciona bien con datos continuos dispersos. Solo traza con datos específicos como `[10, 10, 10, 11, 12]` lo revela.

## Fix mínimo

Cuando `mad == 0` no hay dispersión detectable, así que lo correcto es no filtrar (o usar otra medida de escala):

```python
if mad == 0:
    return sum(data) / len(data)  # o usar desviación media / std como respaldo
threshold = 3 * mad
```

Alternativamente: `threshold = max(3 * mad, epsilon)` con un epsilon relativo a la escala de los datos.

## Bonus: otro caso borde (menos sutil)

```python
remove_outliers_and_average([])  # ZeroDivisionError en sum(data) / len(data)
```

La guarda `len(data) < 3` no protege contra la lista vacía. Nota que el resto del código está bien: `find_median` es correcto para listas no vacías, y `filtered` nunca puede quedar vacío (la mediana siempre tiene desviación 0 ≤ threshold), así que no hay división por cero ahí — el fallo real es el colapso de la MAD.
