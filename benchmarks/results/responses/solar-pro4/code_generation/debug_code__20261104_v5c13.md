## 🐛 Bugs Identificados

### 1. **División por cero** (Línea 13)
```python
average = total / len(processed)
```
**Problema:** Si no hay órdenes con status `'pending'`, `processed` es una lista vacía y `len(processed)` es 0, lo que genera un `ZeroDivisionError`.

**Solución:** Verificar si `processed` tiene elementos antes de calcular el promedio.

---

### 2. **Mutación del diccionario original** (Líneas 9-10)
```python
order['final_price'] = final_price
order['status'] = 'processed'
```
**Problema:** Se modifican los diccionarios originales de la lista `orders`. Esto puede causar efectos secundarios no deseados si los datos originales se usan en otra parte del programa.

**Solución:** Crear copias de los diccionarios antes de modificar los campos.

---

### 3. **Campo `count` incorrecto** (Línea 17)
```python
'count': len(orders)
```
**Problema:** El enunciado indica que `count` debería reflejar la cantidad de órdenes procesadas, no el total de órdenes recibidas.

**Solución:** Usar `len(processed)` en lugar de `len(orders)`.

## ✅ Código Corregido

```python
def process_orders(orders):
    total = 0
    processed = []
    
    for order in orders:
        if order['status'] == 'pending':
            # Crear copia para evitar mutación del original
            order_copy = order.copy()
            
            discount = order_copy['total'] * 0.1 if order_copy['total'] > 100 else 0
            final_price = order_copy['total'] - discount
            order_copy['final_price'] = final_price
            order_copy['status'] = 'processed'
            
            total += final_price
            processed.append(order_copy)

    # Evitar división por cero
    average = total / len(processed) if processed else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)  # Corregido: cantidad procesada, no total
    }
```
