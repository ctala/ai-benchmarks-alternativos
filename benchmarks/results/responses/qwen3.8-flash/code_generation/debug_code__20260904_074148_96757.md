## Bugs identificados

### 1. División por cero si no hay órdenes `pending`

En esta línea:

```python
average = total / len(processed)
```

Si no existe ninguna orden con `status == 'pending'`, entonces `processed` queda vacío.

Eso provoca:

```python
ZeroDivisionError: division by zero
```

También puede ocurrir si `orders` está vacío o si ninguna orden cumple la condición.

---

### 2. Muta el diccionario original

En esta parte:

```python
order['final_price'] = final_price
order['status'] = 'processed'
processed.append(order)
```

Se está modificando directamente el diccionario `order` que viene en la lista original `orders`.

Eso significa que el estado inicial del input cambia como efecto colateral.

Por ejemplo, si alguien llama a la función y después inspecciona `orders`, verá que las órdenes fueron modificadas, aunque no debería ser así.

Además, `processed.append(order)` guarda una referencia al mismo diccionario original, no una copia.

---

### 3. `'count'` debería ser `len(processed)`, no `len(orders)`

El código devuelve:

```python
'count': len(orders)
```

Eso cuenta todas las órdenes recibidas, no las órdenes procesadas.

Si por ejemplo hay 10 órdenes, pero solo 3 están `pending`, el contador correcto debería ser 3, no 10.

## Versión corregida

```python
import copy


def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] == 'pending':
            # Copiamos la orden para no mutar el diccionario original
            order_copy = copy.deepcopy(order)

            discount = order_copy['total'] * 0.1 if order_copy['total'] > 100 else 0
            final_price = order_copy['total'] - discount

            order_copy['final_price'] = final_price
            order_copy['status'] = 'processed'

            total += final_price
            processed.append(order_copy)

    # Evitamos división por cero si no hay órdenes procesadas
    average = total / len(processed) if processed else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)
    }
```

## Explicación de los cambios

### Evitar división por cero

Antes:

```python

```

Ahora:

```python
average = total / len(processed) if processed else 0
```

Si `processed` está vacío, el promedio es `0`.

---

### No mutar el diccionario original

Antes:

```python
order['final_price'] = final_price
order['status'] = 'processed'
processed.append(order)
```

Ahora:

```python
order_copy = copy.deepcopy(order)

order_copy['final_price'] = final_price
order_copy['status'] = 'processed'

processed.append(order_copy)
```

Se trabaja sobre una copia, por lo que el input original permanece intacto.

Si solo necesitas copiar claves de primer nivel, también podrías usar:

```python

```

Pero `copy.deepcopy(order)` es más seguro si las órdenes contienen estructuras anidadas, como listas o diccionarios dentro de `order`.

---

### Devolver el conteo correcto de órdenes procesadas

Antes:

```python
'count': len(orders)
```

Ahora:

```python
'count': len(processed)
```

Esto devuelve cuántas órdenes realmente fueron procesadas.
