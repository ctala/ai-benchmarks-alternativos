## Respuesta completa

Hay **3 bugs principales** (y un efecto colateral derivado del segundo). Aquí está el análisis paso a paso:

---

### 1. `ZeroDivisionError` (división por cero)
Si ninguna orden tiene `status == 'pending'`, `processed` queda vacío (`len(processed) == 0`). La línea:
```python
average = total / len(processed)
```
lanza una excepción.

**Fix:** comprobar si `processed` tiene elementos antes de dividir.

---

### 2. Mutación del diccionario original (y de la lista original)
En Python, `order` es una **referencia** al diccionario que vive dentro de la lista `orders`. Al hacer:
```python
order['final_price'] = final_price
order['status'] = 'processed'
processed.append(order)
```
estás modificando **el objeto original** y luego guardando esa misma referencia en `processed`. Esto es un efecto secundario peligroso.

**Fix:** crear una copia (`order.copy()`) para trabajar sobre ella y añadir la copia a `processed`, dejando intacto el original.

> Nota: `.copy()` hace una copia superficial, que aquí es suficiente porque los valores (`total`, `status`, etc.) son inmutables (int/float/str).

---

### 3. `count` cuenta todas las órdenes de entrada
```python
'count': len(orders)
```
devuelve el total de elementos pasados a la función, no las que realmente fueron procesadas.

**Fix:** usar `len(processed)`.

---

## Código corregido

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] == 'pending':
            # 1. Copiar para NO mutar el diccionario original
            new_order = order.copy()
            
            # 2. Calcular descuento y precio final sobre la copia
            discount = new_order['total'] * 0.1 if new_order['total'] > 100 else 0
            final_price = new_order['total'] - discount
            
            new_order['final_price'] = final_price
            new_order['status'] = 'processed'
            
            total += final_price
            # 3. Guardar la copia, no la referencia original
            processed.append(new_order)

    # 4. Evitar división por cero si no hay órdenes pendientes
    average = total / len(processed) if len(processed) > 0 else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)  # 5. Contar solo las procesadas
    }
```

### Resumen de cambios
| Línea / Concepto | Problema | Solución aplicada |
|---|---|---|
| `order['final_price']...` | Mutaba original | `new_order = order.copy()` |
| `processed.append(order)` | Añadía referencia original | `processed.append(new_order)` |
| `total / len(processed)` | `ZeroDivisionError` | `if len(processed) > 0 else 0` |
| `'count': len(orders)` | Contaba entradas, no procesadas | `'count': len(processed)` |

Con esto la función es segura, no produce efectos secundarios en la entrada y maneja correctamente listas vacías de órdenes pendientes.
