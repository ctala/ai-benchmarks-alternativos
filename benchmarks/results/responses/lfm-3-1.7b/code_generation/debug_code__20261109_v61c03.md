## Respuesta completa

**Bug 1 – División por cero cuando no hay pedidos “pending”**  
En la línea  

```python
average = total / len(processed)
```

si el bucle no encuentra ningún pedido con `status == 'pending'` (o ninguno es procesable) entonces `processed` queda vacío y `len(processed)` es **0**. El resultado de `total / 0` lanza un error `ZeroDivisionError`.  

**Solución:** comprobar si `processed` tiene elementos antes de dividir. Si está vacío, asignamos `0.0` (o `None`) como promedio.

---

**Bug 2 – Se muta el diccionario original**  
El código hace  

```python
order['final_price'] = final_price
order['status'] = 'processed'
```

y modifica directamente el objeto `order` que proviene del argumento `orders`. Esto cambia los datos del mismo diccionario que el llamador, lo cual suele ser indeseable o puede causar efectos colaterales inesperados.

**Solución:** trabajemos sobre una copia temporal (`order.copy()`) para crear el diccionario modificado y añadimos ese diccionario a la lista `processed`. Así el diccionario original sigue intacto.

---

**Bug 3 – La clave `count` usa `len(orders)` en vez de el número de pedidos procesadas**  
Según el comentario del propio código, `count` debe representar cuántos pedidos se convirtieron en *processed*. Actualmente se escribe `len(orders)`, que cuenta todos los elementos de entrada, no solo los que fueron actualizados.

**Solución:** cambiarlo a `len(processed)`.

```python
def process_orders(orders):
    """
    Recibe una lista de diccionarios 'ordering' (cada uno tiene al menos las claves
    'status' y 'total'). 
    Para cada orden cuyo 'status' sea 'pending':
        - aplica un descuento del 10 % si su 'total' excede 100, en caso contrario no hay descuento.
        - calcula 'final_price' = total - descuento.
        - crea una copia del diccionario y le añade las claves 'final_price' y 'status'.
    Devuelve un diccionario con:
        - 'processed': lista de las copias modificadas (solo los órdenes que eran 'pending').
        - 'total': suma de los 'final_price' de los órdenes procesados.
        - 'average': total / cantidad de procesados (0.0 si no hay ninguno).
        - 'count': número de elementos en 'processed' (no len(orders)).
    """
    total = 0          # acumulador de precios finales
    processed = []     # lista de objetos ya procesados

    for order in orders:
        # Usamos .get() para no lanzar KeyError si alguna clave falta
        if order.get('status') == 'pending':
            total_order = order.get('total', 0)

            # Descuento del 10 % si el total supera 100, sino 0
            discount = total_order * 0.1 if total_order > 100 else 0
            final_price = total_order - discount

            # Trabajamos sobre una copia para no mutar el original
            updated_order = order.copy()
            updated_order['final_price'] = final_price
            updated_order['status'] = 'processed'

            total += final_price
            processed.append(updated_order)

    num_processed = len(processed)
    # Evitamos división por cero
    average = total / num_processed if num_processed != 0 else 0.0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': num_processed
    }
```

#### ¿Qué se ha cambiado?

| Línea / Concepto | Antes | Después |
|------------------|-------|---------|
| Creación de `processed` | sin copia, se APPENDaba la misma referencia | se crea `updated_order = order.copy()` antes de modificar |
| Cálculo de descontocio | `discount = order['total'] * 0.1 if order['total'] > 100 else 0` (puede haberse escrito mal) | usada `total_order = order.get('total', 0)` y la lógica idéntica pero dentro de un bloque claro |
| Asignación de campos | directo sobre `order` → mutación del dato original | sobre `updated_order` (copia) → el original permanece intacto |
| Punto medio (`average`) | `total / len(processed)` → riesgo de `ZeroDivisionError` | `total / num_processed if num_processed != 0 else 0.0` |
| Clave `count` en el retorno | `len(orders)` | `num_processed = len(processed)` → `count: num_processed` |

Con estos cambios el código respeta los tres problemas señalados, evita errores de división por cero y no altera los diccionarios pasados como argumento.
