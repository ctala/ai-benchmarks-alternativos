## Respuesta completa

Los tres bugs son:

1. **División por cero:** si no hay órdenes con estado `'pending'` (o la lista está vacía), `processed` queda vacío. Calcular `total / len(processed)` genera un `ZeroDivisionError`. En ese caso, podemos devolver `0` como promedio.

2. **Modificación de los datos originales:** `order` es una referencia al diccionario dentro de `orders`. Al asignar `final_price` y cambiar `status`, se modifica también la entrada original. Para evitarlo, hay que copiar el diccionario antes de modificarlo. Una copia superficial (`order.copy()`) basta aquí porque solo se cambian campos de primer nivel.

3. **Conteo incorrecto:** `len(orders)` cuenta todas las órdenes, incluidas las que no se procesaron. El valor correcto es `len(processed)`.

### Versión corregida

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] == 'pending':
            processed_order = order.copy()

            discount = order['total'] * 0.1 if order['total'] > 100 else 0
            final_price = order['total'] - discount

            processed_order['final_price'] = final_price
            processed_order['status'] = 'processed'

            total += final_price
            processed.append(processed_order)

    count = len(processed)
    average = total / count if count > 0 else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': count
    }
```

Esta versión conserva la regla de descuento original: **10 % únicamente cuando el total supera 100**, sin modificar los diccionarios de entrada.
