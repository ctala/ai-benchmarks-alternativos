## Respuesta completa

Hay tres bugs claros.

**1. División por cero.** Si ninguna orden está en `pending`, `processed` queda vacío y `total / len(processed)` lanza `ZeroDivisionError`.

**2. Mutación del diccionario original.** `order` es una referencia al dict de la lista de entrada. Asignar `order['final_price']` y `order['status']` modifica el objeto del llamador, no una copia.

**3. `count` incorrecto.** Devuelve `len(orders)` (todas las órdenes) en lugar de cuántas se procesaron realmente.

Versión corregida:

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order.get('status') != 'pending':
            continue

        # Copia para no mutar el dict original
        item = dict(order)
        discount = item['total'] * 0.1 if item['total'] > 100 else 0
        final_price = item['total'] - discount
        item['final_price'] = final_price
        item['status'] = 'processed'

        total += final_price
        processed.append(item)

    count = len(processed)
    average = total / count if count else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': count,
    }
```

`dict(order)` hace una copia superficial, suficiente aquí porque solo se reasignan claves de primer nivel. Si `count` es 0, `average` queda en 0 en lugar de fallar.
