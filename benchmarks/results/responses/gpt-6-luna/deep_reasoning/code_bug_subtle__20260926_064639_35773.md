def find_median(numbers):
    sorted_nums = sorted(numbers)
    n = len(sorted_nums)
    mid = n // 2
    if n % 2 == 0:
        return (sorted_nums[mid - 1] + sorted_nums[mid]) / 2
    else:

def remove_outliers_and_average(data):
    if len(data) < 3:
        return sum(data) / len(data)

    median = find_median(data)
    mad = find_median([abs(x - median) for x in data])
    threshold = 3 * mad

    filtered = [x for x in data if abs(x - median) <= threshold]
    return sum(filtered) / len(filtered)

## Respuesta completa

El fallo más claro es con `data == []`. Como `len(data) < 3`, se ejecuta la primera rama:

```python
return sum(data) / len(data)
```

Eso equivale a `0 / 0` y produce `ZeroDivisionError`. La función debería rechazar explícitamente la entrada vacía o definir qué resultado devolver en ese caso.

También puede fallar si se permiten valores `NaN`. Por ejemplo, con `[float('nan')] * 3`, la mediana y el MAD son `NaN`; las comparaciones `abs(x - median) <= threshold` son falsas, así que `filtered` queda vacío y la división final vuelve a producir `ZeroDivisionError`.

Para datos finitos no vacíos, el caso `MAD == 0` no deja necesariamente `filtered` vacío: conserva los valores iguales a la mediana. Sí puede ser una decisión estadística discutible, pero no es por sí sola el error de división.
