## Respuesta completa

Sí, hay 3 bugs. Son independientes entre sí:

### 1. División por cero

```python
average = total / len(processed)
```

Si `orders` está vacía, o si ninguna orden tiene `status == 'pending'`, entonces `processed` queda vacío y `len(processed) == 0`.

Resultado: `ZeroDivisionError` y el programa se rompe.

**Corrección:** proteger la división devolviendo `0` cuando no hay procesadas.

```python
average = total / len(processed) if processed else 0
```

### 2. Mutación del diccionario original

```python
order['final_price'] = final_price
order['status'] = 'processed'
```

`order` no es una copia, es una referencia al diccionario que está dentro de la lista `orders` del llamador. Al modificarlo, modificas los datos originales.

Consecuencias: efecto lateral inesperado, si llamas a la función dos veces la segunda vez ya no encontrará órdenes `pending`, y los datos de entrada quedan "corrompidos".

**Corrección:** trabajar sobre una copia.

```python
new_order = order.copy()  # o copy.deepcopy(order) si hay datos anidados
new_order['final_price'] = final_price
new_order['status'] = 'processed'
processed.append(new_order)
```

### 3. `count` incorrecto

```python
'count': len(orders)
```

Si hay 3 órdenes en total pero solo 2 estaban `pending`, devuelves `processed` con 2 elementos pero `count: 3`. Es inconsistente: `count` debería representar cuántas órdenes fueron procesadas, que es justamente lo que devuelve `processed`.

**Corrección:**

```python
'count': len(processed)
```

### Versión corregida

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] == 'pending':
            # 2. No mutar el original: trabajar con una copia
            new_order = order.copy()

            discount = new_order['total'] * 0.1 if new_order['total'] > 100 else 0
            final_price = new_order['total'] - discount

            new_order['final_price'] = final_price
            new_order['status'] = 'processed'

            total += final_price
            processed.append(new_order)

    # 1. Evitar división por cero
    average = total / len(processed) if processed else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)  # 3. Corregido: antes era len(orders)
    }
```

Ahora `process_orders([])` devuelve `{'processed': [], 'total': 0, 'average': 0, 'count': 0}` sin crashear, la lista original no se modifica, y `count` coincide con la cantidad real de órdenes procesadas.
