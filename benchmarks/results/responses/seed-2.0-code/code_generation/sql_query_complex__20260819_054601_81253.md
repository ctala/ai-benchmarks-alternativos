**user:**

Tengo estas tablas:
- orders (id, customer_id, total, status, created_at)
- customers (id, name, email, country, created_at)
- order_items (id, order_id, product_id, quantity, unit_price)
- products (id, name, category, price)

Escribe una query SQL que muestre:
- Top 10 clientes por revenue total en los ultimos 6 meses
- Con columnas: nombre, email, pais, total_orders, total_revenue, avg_order_value, categoria_mas_comprada

- Solo clientes con al menos 3 ordenes completadas (status = 'completed')

### Consulta SQL Optimizada (compatibilidad principal con **MySQL**, con notas para otros SGBD)
Se usa **CTEs (Expresiones de Tabla Comunes)** para mayor legibilidad y rendimiento, y se cumple TODOS los requisitos:

```sql
WITH 
-- 1. Órdenes VÁLIDAS: Completadas, últimos 6 meses, con su VALOR TOTAL por orden
valid_orders AS (
    SELECT
        o.id AS order_id,
        o.customer_id,
        -- Calcular valor real de la orden desde ítems (evita discrepancias con orders.total)
        SUM(oi.quantity * oi.unit_price) AS order_value
    FROM orders o
    INNER JOIN order_items oi 
        ON o.id = oi.order_id
    WHERE
        o.status = 'completed'
        -- Filtrar últimos 6 meses (ADAPTAR SEGÚN SGBD, ver notas abajo)
        AND o.created_at >= DATE_SUB(CURRENT_DATE(), INTERVAL 6 MONTH)
    GROUP BY o.id, o.customer_id
),

-- 2. Métricas básicas por cliente (filtramos quienes tienen ≥3 órdenes VÁLIDAS)
customer_order_metrics AS (
    SELECT
        vo.customer_id,
        COUNT(vo.order_id) AS total_orders, -- No necesita DISTINCT porque order_id es PK
        SUM(vo.order_value) AS total_revenue,
        AVG(vo.order_value) AS avg_order_value -- Promedio de valor por orden
    FROM valid_orders vo
    GROUP BY vo.customer_id
    -- Filtro OBLIGATORIO: al menos 3 órdenes COMPLETADAS en el período
    HAVING COUNT(vo.order_id) >= 3
),

-- 3. Cantidad de unidades compradas por cliente y categoría (solo órdenes válidas)
customer_category_purchases AS (
    SELECT
        vo.customer_id,
        p.category,
        SUM(oi.quantity) AS total_units -- Medida para "más comprada" (ver notas)
    FROM valid_orders vo
    INNER JOIN order_items oi 
        ON vo.order_id = oi.order_id
    INNER JOIN products p 
        ON oi.product_id = p.id
    GROUP BY vo.customer_id, p.category
),

-- 4. Categoría MÁS COMPRADA por cliente (desempate por orden alfabético de categoría)
top_customer_categories AS (
    SELECT
        customer_id,
        category AS categoria_mas_comprada,
        ROW_NUMBER() OVER (
            PARTITION BY customer_id
            ORDER BY total_units DESC, category ASC -- Desempate por nombre de categoría
        ) AS rn
    FROM customer_category_purchases
)

-- CONSULTA FINAL: Unir datos de clientes + métricas + categoría top
SELECT
    c.name AS nombre,
    c.email AS email,
    c.country AS pais,
    com.total_orders,
    -- (Opcional) Redondear valores monetarios: ROUND(com.total_revenue, 2) AS total_revenue
    com.total_revenue,
    -- (Opcional) Redondear promedio: ROUND(com.avg_order_value, 2) AS avg_order_value
    com.avg_order_value,
    tcc.categoria_mas_comprada
FROM customers c
-- Solo clientes con métricas válidas (≥3 órdenes)
INNER JOIN customer_order_metrics com 
    ON c.id = com.customer_id
-- Solo la categoría más comprada (rn=1)
INNER JOIN top_customer_categories tcc 
    ON c.id = tcc.customer_id 
    AND tcc.rn = 1
-- Orden obligatorio: por revenue DESC
ORDER BY com.total_revenue DESC
-- Top 10 clientes
LIMIT 10;
```

### 📌 Notas Importantes (Adaptaciones y Aclaraciones)
---

#### 1. **Compatibilidad por SGBD (Filtro de Fecha)**
La consulta usa sintaxis de **MySQL**. Para otros SGBD, cambia la condición de fecha en `valid_orders`:
- **PostgreSQL**: `AND o.created_at >= CURRENT_DATE - INTERVAL '6 months'`
- **SQL Server**: `AND o.created_at >= DATEADD(MONTH, -6, GETDATE())`
- **Oracle**: `AND o.created_at >= ADD_MONTHS(SYSDATE, -6)`

---

#### 2. **¿Qué se considera "Categoría Más Comprada"?**
La consulta usa **CANTIDAD DE UNIDADES VENDIDAS** (más común para "más comprada"). Si quieres usar **REVENUE POR CATEGORÍA**, modifica la CTE `customer_category_purchases`:
```sql
-- Cambia SUM(oi.quantity) por:
SUM(oi.quantity * oi.unit_price) AS total_revenue_category
```
Y el `ORDER BY` en `top_customer_categories`:
```sql
ORDER BY total_revenue_category DESC, category ASC
```

---

#### 3. **Filtro de "Al Menos 3 Órdenes Completadas"**
La consulta filtra **órdenes completadas EN LOS ÚLTIMOS 6 MESES** (coherente con el revenue del período). Si quieres que el filtro sea **TODAS LAS ÓRDENES COMPLETADAS DEL CLIENTE (históricas)**, agrega esta CTE:
```sql
-- Agrega antes de valid_orders:
all_completed_orders AS (
    SELECT customer_id, COUNT(id) AS total_completed_orders
    FROM orders
    WHERE status = 'completed'
    GROUP BY customer_id
    HAVING COUNT(id) >= 3
)
```
Y modifica `customer_order_metrics` para unir con `all_completed_orders`:
```sql
INNER JOIN all_completed_orders aco ON vo.customer_id = aco.customer_id
```
Y elimina el `HAVING` de `customer_order_metrics`.

---

#### 4. **Valores Monetarios (Opcional)**
Si tus columnas `unit_price` y `price` son de tipo `DECIMAL` (recomendado), no necesitas redondear. Si son `FLOAT` o `DOUBLE`, usa `ROUND()` para evitar errores de precisión (ej: `ROUND(com.total_revenue, 2)`).
