## Explicación de cada bug (con ejemplos prácticos)
El código tiene 3 bugs claros, cada uno con causas y efectos específicos:

---

### Bug 1: División por cero (`ZeroDivisionError`)
#### Causa
La línea `average = total / len(processed)` no maneja el caso en que **no haya órdenes pendientes** (la lista `processed` está vacía, por lo que `len(processed) = 0`).
#### Ejemplo que provoca el error
```python
# Caso: Todas las órdenes son "completed" (no hay pendientes para procesar)
orders_sin_pendientes = [
    {"status": "completed", "total": 50},
    {"status": "cancelled", "total": 120}
]
process_orders(orders_sin_pendientes)  # Lanza: ZeroDivisionError: division by zero
```

---

### Bug 2: Mutación del diccionario original (efecto secundario no deseado)
#### Causa
En Python, los diccionarios son **tipos mutables y pasados por referencia**. Cuando se modifica `order["final_price"]` o `order["status"]`, se está cambiando el diccionario **ORIGINAL** de la lista `orders` de entrada, no una copia. Esto corrompe los datos de entrada sin querer.
#### Ejemplo que demuestra el bug
```python
orden_original = {"status": "pending", "total": 150}
orders = [orden_original]

process_orders(orders)

# El diccionario original SE MODIFICÓ sin permiso:
print(orden_original)
# Salida ESPERADA (sin bug): {"status": "pending", "total": 150}
# Salida REAL (con bug): {"status": "processed", "total": 150, "final_price": 135.0}
```

---

### Bug 3: Valor incorrecto en la clave `count`
#### Causa
La clave `count` del retorno usa `len(orders)` (cantidad TOTAL de órdenes de entrada) en lugar de `len(processed)` (cantidad de órdenes **EFECTIVAMENTE PROCESADAS**).
#### Ejemplo que demuestra el bug
```python
orders = [
    {"status": "pending", "total": 80},   # Se procesa
    {"status": "completed", "total": 100}, # No se procesa
    {"status": "cancelled", "total": 50}   # No se procesa
]
resultado = process_orders(orders)

# Valor ESPERADO de "count": 1 (solo 1 orden procesada)
# Valor REAL de "count": 3 (len(orders) = 3)
```

## Versión corregida
Se solucionan todos los bugs con estos cambios:
1. Manejar el caso de `processed` vacía para evitar la división por cero.
2. Crear una **copia del diccionario original** antes de modificarlo (no altera los datos de entrada).
3. Cambiar `len(orders)` por `len(processed)` en la clave `count`.

> Nota: Usamos `order.copy()` (copia superficial) porque los diccionarios de órdenes tienen datos básicos (números, cadenas). Si hubiera datos anidados, usaríamos `copy.deepcopy()` del módulo `copy`.

```python
def process_orders(orders):
    total = 0
    processed = []
    
    for order in orders:
        if order['status'] == 'pending':
            # ✅ Bug 2 solucionado: Copiamos el diccionario original para no mutarlo
            new_order = order.copy()  # Copia superficial (suficiente para este caso)
            
            # Cálculo de descuento (igual que antes, pero sobre la copia)
            discount = new_order['total'] * 0.1 if new_order['total'] > 100 else 0
            final_price = new_order['total'] - discount
            
            # Modificamos SOLO la copia (no el original)
            new_order['final_price'] = final_price
            new_order['status'] = 'processed'
            
            # Actualizamos totales y lista de procesados (usamos la copia)
            total += final_price
            processed.append(new_order)

    # ✅ Bug 1 solucionado: Manejamos caso de processed vacío
    average = total / len(processed) if processed else 0.0  # Promedio 0 si no hay procesadas

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)  # ✅ Bug 3 solucionado: Usamos len(processed)
    }
```
