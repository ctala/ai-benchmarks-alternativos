def find_median(numbers):
    sorted_nums = sorted(numbers)
    n = len(sorted_nums)
    mid = n // 2
    if n % 2 == 0:
        return (sorted_nums[mid - 1] + sorted_nums[mid]) / 2
    else:
        return sorted_nums[mid]

def remove_outliers_and_average(data):
    if len(data) < 3:
        return sum(data) / len(data)

    median = find_median(data)
    mad = find_median([abs(x - median) for x in data])
    threshold = 3 * mad

    filtered = [x for x in data if abs(x - median) <= threshold]
    return sum(filtered) / len(filtered)

### Identificación del Bug Sutil
El bug se produce en **casos donde la lista filtrada `filtered` queda VACÍA**, lo que genera una **excepción de división por cero** al ejecutar `sum(filtered) / len(filtered)`.

Aunque matemáticamente esto no debería ocurrir (por definición de la mediana y MAD), se produce por **errores de representación de números de punto flotante en Python** o por casos límite de datos específicos.

---

### Exactamente Cuándo Falla
El bug aparece **cuando se cumplen TODAS estas condiciones**:
1. La longitud de `data` es ≥3 (por lo que se ejecuta el filtrado, no el caso inicial).
2. El **MAD (Median Absolute Deviation)** es **cero** (lo que significa que al menos la mitad de los datos son *exactamente* iguales a la mediana, sin error de punto flotante).
3. **Todos los datos que deberían ser iguales a la mediana tienen un error de representación de punto flotante** que los hace *ligeramente diferentes* de la mediana calculada.

---

### Por Qué Falla
Vamos a desglosar el razonamiento:
1. **MAD = 0 implica**: La mediana de las desviaciones absolutas (`|x - mediana|`) es 0. Por definición de mediana, esto requiere que **al menos la mitad de las desviaciones sean 0** (es decir, al menos la mitad de los datos son *exactamente* iguales a la mediana).
2. **Umbral = 3*MAD = 0**: La condición de filtrado `abs(x - mediana) <= threshold` se convierte en `abs(x - mediana) <= 0`, que **solo es verdadera si `x == mediana`** (porque el valor absoluto no puede ser negativo).
3. **Error de punto flotante**: En Python, operaciones como `0.1 + 0.2` no devuelven `0.3` exactamente, sino `0.30000000000000004` (por la representación binaria de números de coma flotante).
4. **Resultado**: Los datos que deberían ser iguales a la mediana son *ligeramente diferentes* (por error de punto flotante), por lo que **ningún dato cumple la condición de filtrado** → `filtered` queda vacía → `sum(filtered)/len(filtered)` lanza `ZeroDivisionError`.
