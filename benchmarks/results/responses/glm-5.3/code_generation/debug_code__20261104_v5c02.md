# Análisis de los bugs

## Bug 1: División por cero

```python
average = total / len(processed)
```

Si ningún pedido tiene estado `'pending'`, la lista `processed` queda vacía y `len(processed)` es `0`:

```python
process_orders([{'status': 'shipped', 'total': 50}])
# ZeroDivisionError: division by zero
```

**Corrección:** verificar antes de dividir (con `0` o `None` según la semántica que se quiera: `0` = "promedio cero", `None` = "no hubo pedidos").

## Bug 2: Mutación del diccionario original

```python
order['final_price'] = final_price
order['status'] = 'processed'
```

Estas líneas modifican los diccionarios de la lista de entrada, lo que causa un **efecto secundario oculto**. El problema más grave: la función **no es idempotente** — si se llama dos veces con la misma lista, la segunda no procesa nada porque ya no quedan pedidos `'pending'`:

```python
orders = [{'status': 'pending', 'total': 150}]

r1 = process_orders(orders)
print(orders[0]['status'])   # 'processed' → ¡el original cambió!

r2 = process_orders(orders)  # no procesa nada esta vez
```

**Corrección:** trabajar sobre una copia. Aquí basta con una copia superficial (`order.copy()`) porque solo se modifican claves de primer nivel; si hubiera estructuras anidadas que se alteran, haría falta `copy.deepcopy`.

## Bug 3: `'count'` incoherente

```python
'count': len(orders)
```

Cuenta **todos** los pedidos, pero el resto del resultado (`processed`, `total`, `average`) se refiere solo a los procesados:

```python
orders = [
    {'status': 'pending', 'total': 150},
    {'status': 'shipped', 'total': 200},
]
process_orders(orders)['count']  # → 2, pero solo se procesó 1
```

Es un bug típico que se propaga silenciosamente a reportes y dashboards.

# Versión corregida

```python
def process_orders(orders):
    total = 0
    processed = []
    for order in orders:
        if order['status'] == 'pending':
            new_order = order.copy()  # Bug 2: no mutar el original
            discount = new_order['total'] * 0.1 if new_order['total'] > 100 else 0
            final_price = new_order['total'] - discount
            new_order['final_price'] = final_price
            new_order['status'] = 'processed'
            total += final_price
            processed.append(new_order)

    count = len(processed)                    # Bug 3: contar solo los procesados
    average = total / count if count > 0 else 0  # Bug 1: evitar división por cero

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': count
    }
```

Nota que guardo `count` en una variable y la reutilizo: conecta las correcciones de los bugs 1 y 3 y evita calcular `len()` dos veces.

# Consideraciones adicionales (no estaban en la lista)

- **Floats para dinero:** los descuentos con `0.1` pueden acumular errores de redondeo (el clásico `0.1 + 0.2 == 0.30000000000000004`). Para dinero real conviene `decimal.Decimal`, o al menos `round(final_price, 2)`.
- **Claves faltantes:** `order['status']` lanza `KeyError` si la clave no existe. Se puede usar `order.get('status')` para tolerarlo, aunque en muchos contextos fallar rápido con un error claro es preferible.
