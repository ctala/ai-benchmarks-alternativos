## Respuesta completa

Tienes razón, ese código tiene esos 3 bugs. Te los explico uno por uno:

### 1. División por cero
```python
average = total / len(processed)
```
Si `orders` está vacío, o si ninguna orden tiene `status == 'pending'`, entonces `processed` será `[]` y `len(processed)` será `0`. Eso lanza `ZeroDivisionError`.

**Fix:** Calcular el promedio solo si hay elementos, si no devolver 0.

### 2. Muta el diccionario original
```python
order['final_price'] = final_price
order['status'] = 'processed'
```
`order` es una referencia al diccionario que viene en la lista `orders`. Al modificarlo directamente estás cambiando los datos originales fuera de la función. Esto es un efecto secundario inesperado.

**Fix:** Crear una copia del diccionario con `.copy()` o `{**order, ...}` antes de modificarlo.

### 3. `count` incorrecto
```python
'count': len(orders)
```
Estás devolviendo el total de órdenes recibidas, no el total de órdenes que realmente procesaste. Debería ser `len(processed)`.

**Fix:** Usar `len(processed)`.

### Versión corregida:

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order.get('status') == 'pending':
            order_total = order.get('total', 0)
            discount = order_total * 0.1 if order_total > 100 else 0
            final_price = order_total - discount

            # 2. No mutamos el original, creamos una copia
            new_order = {**order, 'final_price': final_price, 'status': 'processed'}

            total += final_price
            processed.append(new_order)

    # 1. Evitamos división por cero
    average = total / len(processed) if processed else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        # 3. Contamos solo las procesadas
        'count': len(processed)
    }
```

Con esto la función es segura con listas vacías, no tiene efectos secundarios y devuelve las métricas correctas.
