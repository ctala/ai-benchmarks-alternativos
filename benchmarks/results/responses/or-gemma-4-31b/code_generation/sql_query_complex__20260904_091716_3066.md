Escribe una query SQL que muestre:
- Top 10 clientes por revenue total en los ultimos 6 meses
- Con columnas: nombre, email, pais, total_orders, total_revenue, avg_order_value, categoria_mas_comprada
- Ordena por total_revenue DESC
- Solo clientes con al menos 3 ordenes completadas (status = 'completed')


## Respuesta completa

Para resolver este problema, la parte más compleja es obtener la "categoría más comprada", ya que requiere un cálculo independiente al de las sumas totales. La mejor forma de abordar esto es utilizando **CTEs (Common Table Expressions)** y una **Window Function** (`ROW_NUMBER`).

Aquí tienes la query (escrita en PostgreSQL/Standard SQL, que es el estándar más común):

```sql
WITH filtered_orders AS (
    -- 1. Filtramos órdenes completadas en los últimos 6 meses
    SELECT id, customer_id, total
    FROM orders
    WHERE status = 'completed' 
      AND created_at >= CURRENT_DATE - INTERVAL '6 months'
),
customer_stats AS (
    -- 2. Calculamos métricas generales de los clientes
    SELECT 
        customer_id, 
        COUNT(id) AS total_orders, 
        SUM(total) AS total_revenue, 
        AVG(total) AS avg_order_value
    FROM filtered_orders
    GROUP BY customer_id
    HAVING COUNT(id) >= 3
),
category_ranking AS (
    -- 3. Determinamos la categoría más comprada por cada cliente
    SELECT 
        o.customer_id, 
        p.category,
        ROW_NUMBER() OVER(PARTITION BY o.customer_id ORDER BY SUM(oi.quantity) DESC) as rank
    FROM filtered_orders o
    JOIN order_items oi ON o.id = oi.order_id
    JOIN products p ON oi.product_id = p.id
    GROUP BY o.customer_id, p.category
)
-- 4. Unimos todo para el resultado final
SELECT 
    c.name, 
    c.email, 
    c.country, 
    cs.total_orders, 
    cs.total_revenue, 
    cs.avg_order_value, 
    cr.category AS categoria_mas_comprada
FROM customers c
JOIN customer_stats cs ON c.id = cs.customer_id
JOIN category_ranking cr ON c.id = cr.customer_id AND cr.rank = 1
ORDER BY cs.total_revenue DESC
LIMIT 10;
```

### Explicación detallada de la solución:

1.  **`filtered_orders`**: Creamos una tabla temporal con las órdenes que cumplen los criterios básicos (estatus 'completed' y fecha $\ge$ 6 meses). Esto evita repetir los filtros en los siguientes pasos y mejora el rendimiento.
2.  **`customer_stats`**: Aquí realizamos las agregaciones numéricas. Usamos la cláusula `HAVING COUNT(id) >= 3` para descartar inmediatamente a los clientes que no tengan el mínimo de órdenes requeridas.
3.  **`category_ranking`**:
    *   Unimos las órdenes filtradas con los productos.
    *   Agrupamos por cliente y categoría para sumar la cantidad de productos comprados.
    *   Usamos `ROW_NUMBER() OVER(PARTITION BY customer_id ORDER BY SUM(quantity) DESC)`. Esto le asigna el número `1` a la categoría que el cliente más compró en cantidad.
4.  **Query Final**:
    *   Unimos la tabla de clientes con las estadísticas y el ranking.
    *   Filtramos `cr.rank = 1` para quedarnos únicamente con la categoría más popular de cada cliente.
    *   Ordenamos por `total_revenue DESC` y limitamos a los 10 mejores.

### Notas según el motor de base de datos:
- **MySQL**: Si usas una versión antigua de MySQL que no soporta `INTERVAL '6 months'`, usa `DATE_SUB(NOW(), INTERVAL 6 MONTH)`.
- **SQL Server**: Cambia `CURRENT_DATE - INTERVAL '6 months'` por `DATEADD(month, -6, GETDATE())`.
- **Rendimiento**: Esta query es eficiente ya que primero reduce el universo de datos (filtros de fecha y status) antes de realizar los joins más pesados con `order_items` y `products`.
