def find_median(numbers):
    sorted_nums = sorted(numbers)
    n = len(sorted_nums)
    mid = n // 2
    if n % 2 == 0:

## Respuesta completa

## El bug: MAD = 0 cuando más de la mitad de los datos son iguales

### Cuándo falla
Falla cuando **más de la mitad de los valores son idénticos**. En ese caso la mediana coincide con ese valor repetido y más de la mitad de las desviaciones `abs(x - median)` son `0`. Entonces:

```python
mad = 0  →  threshold = 3 * 0 = 0
filtered = [x for x in data if abs(x - median) <= 0]   # solo x == median
```

El filtro deja de ser "descarta lo que está muy lejos" y pasa a ser **"descarta todo lo que no sea exactamente igual a la mediana"**.

### Ejemplos

```python
remove_outliers_and_average([10, 10, 10, 11, 12])
# median = 10, desviaciones = [0,0,0,1,2], MAD = 0
# filtered = [10,10,10] → devuelve 10.0
# Esperado: 11 y 12 no son outliers razonables (promedio ≈ 10.6)

remove_outliers_and_average([5, 5, 5, 5, 6, 7])
# MAD = 0 → devuelve 5.0 (se descartan 6 y 7)

remove_outliers_and_average([1, 1, 1, 9])
# MAD = 0 → devuelve 1.0
```

Por contraste, `[10, 11, 12, 13, 14]` funciona bien, porque el MAD no es 0.

### Por qué es sutil
- **No lanza excepción.** `filtered` nunca queda vacío en este caso, porque los valores iguales a la mediana siempre pasan el filtro. Devuelve un número plausible pero incorrecto.
- **El algoritmo es correcto en general.** El fallo aparece solo con datos discretos, redondeados, con muchos repetidos o saturados (lecturas de sensores enteras, notas, ceros frecuentes, etc.).
- **Es una discontinuidad.** `[10,10,10,11,12]` da 10.0, pero con `[10,10,11,11,12]` el MAD es 1 y se conservan todos los valores. Un cambio mínimo en los datos produce un resultado muy distinto.

La condición exacta es:
- n impar: al menos `(n+1)/2` valores iguales a la mediana.
- n par: al menos `n/2 + 1` valores iguales.

### Fallos secundarios (casos límite)
- **Lista vacía:** `len(data) < 3` es verdadero y `sum([]) / 0` lanza `ZeroDivisionError`.
- **NaN en los datos:** `sorted` se comporta de forma impredecible con NaN. Si la mediana resulta NaN, todas las comparaciones `<=` dan `False`, `filtered` queda vacío y se produce `ZeroDivisionError`. Con `inf` ocurre algo parecido, porque `inf - inf = nan`.

### Corrección posible

```python
def remove_outliers_and_average(data):
    if not data:
        raise ValueError("data vacío")
    if len(data) < 3:
        return sum(data) / len(data)

    median = find_median(data)
    mad = find_median([abs(x - median) for x in data])

    if mad == 0:
        # Fallback: no se puede estimar dispersión con MAD;
        # usar la desviación media absoluta o no filtrar.
        meanad = sum(abs(x - median) for x in data) / len(data)
        if meanad == 0:           # todos iguales
            return median
        threshold = 3 * 1.253 * meanad   # estimador alternativo de escala
    else:
        threshold = 3 * 1.4826 * mad     # MAD escalado para equivaler a σ

    filtered = [x for x in data if abs(x - median) <= threshold]
    return sum(filtered) / len(filtered)
```
