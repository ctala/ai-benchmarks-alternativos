## Cómo usarlo

**1. Importar:** en n8n → menú `···` → *Import from File / Clipboard* → pega el JSON.

**2. Configurar credenciales** (los IDs son placeholders, hay que reasignarlos en la UI):
- **OpenAI**: nodo `Clasificar con OpenAI` → selecciona tu credencial `OpenAI API`.
- **Slack**: los 3 nodos Slack → credencial `Slack API` (OAuth2 o Bot Token con scope `chat:write`).

**3. Slack:** invita al bot a cada canal (`/invite @tu-bot` en `#support`, `#sales`, `#general`). Si prefieres IDs de canal en vez de nombres, cambia `"mode": "name"` por `"mode": "id"` y pon `C0123456789`.

**4. Probar:**

```bash
curl -X POST https://TU-N8N/webhook-test/clasificar-mensaje \
  -H "Content-Type: application/json" \
  -d '{"email":"ana@empresa.com","message":"La app se cierra al subir un archivo, error 500"}'
```

## Notas de diseño

| Nodo | Por qué está |
|---|---|
| `¿Datos Válidos?` | Evita gastar llamadas a OpenAI con payloads incompletos. |
| `jsonOutput: true` + `temperature: 0` | Fuerza salida JSON determinista del modelo. |
| `Normalizar Clasificación` | Blindaje: parsea la respuesta venga como objeto o string, limpia ```` ```json ````, y fuerza a `otro` cualquier valor inesperado. Recupera `email`/`message` originales vía `$('Extraer Datos').item`. |
| `fallbackOutput: 2` | Si algo raro llegara al Switch, cae en la salida `otro` (#general) en vez de perderse. |

**Ajustes opcionales:**
- Cambia `gpt-4o-mini` por `gpt-4o` si necesitas más precisión (más coste).
- Para responder al cliente con la categoría, cambia el webhook a `responseMode: "responseNode"` y añade un nodo `Respond to Webhook` al final de cada rama.
- Si tu instancia de n8n es antigua y no reconoce `@n8n/n8n-nodes-langchain.openAi`, sustituye ese nodo por `n8n-nodes-base.openAi` (resource: `chat`) o por un `HTTP Request` a `https://api.openai.com/v1/chat/completions` — el nodo `Normalizar Clasificación` ya contempla ambos formatos de salida.
