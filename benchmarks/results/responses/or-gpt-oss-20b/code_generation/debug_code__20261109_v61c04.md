## Respuesta completa

## 1. Bug #1 – **División por cero cuando no hay órdenes pendientes**

```python
average = total / len(processed)      # <‑‑ aquí se divide por 0 si processed == []
```

Cuando no hay órdenes con `status == 'pending'`, la lista `processed` queda vacía.  
`len(processed)` es 0 y cualquier división por ese valor lanza `ZeroDivisionError`.

**Corrección**  
Calcular el promedio solo cuando haya al menos una orden procesada; de lo contrario asignar `0` (o `None` si prefieres indicar “no disponible”).

```python
average = total / len(processed) if processed else 0
```

---

## 2. Bug #2 – **Mutación de los diccionarios originales**

```python
order['final_price'] = final_price
order['status'] = 'processed'
```

Al asignar directamente sobre `order` se modifica el objeto que ya está en `orders`.  
Si el llamador necesita conservar los datos originales, la función está alterando su entrada.

**Corrección**  
Crear una copia *shallow* del diccionario antes de modificarlo.  
`order.copy()` (o `dict(order)`) es suficiente porque los valores internos son primitivos (`int`, `float`, `str`).  

```python
new_order = order.copy()
new_order['final_price'] = final_price
new_order['status'] = 'processed'
```

El campo `count` pretende indicar cuántas órdenes se han procesado, pero el código devuelve la longitud de la lista original, que incluye órdenes `pending`, `canceled`, etc.

'count': len(processed)

## Código corregido completo

```python
def process_orders(orders):
    """
    Procesa solo las órdenes con status 'pending':
        * Le aplica un descuento del 10 % si el total supera los 100.
        * Cambia su status a 'processed'.
        * Añade el campo 'final_price' con el importe ya descontado.
        * No modifica los diccionarios que llegaron como argumento.

    Devuelve un diccionario con:
        * processed : lista de órdenes procesadas (copia de los originales)
        * total     : suma de los precios finales
        * average   : precio medio de las órdenes procesadas (0 si no hay)
        * count     : número de órdenes procesadas
    """
    processed = []
    total = 0.0

    for order in orders:
        if order.get('status') == 'pending':
            # Copiamos el diccionario para no mutar el original
            new_order = order.copy()

            discount = new_order['total'] * 0.10 if new_order['total'] > 100 else 0.0
            new_order['final_price'] = new_order['total'] - discount
            new_order['status'] = 'processed'

            total += new_order['final_price']
            processed.append(new_order)

    average = total / len(processed) if processed else 0.0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': len(processed)
    }
```

| Línea original | Cambio realizado | Motivo |
|----------------|------------------|--------|
| `order['final_price'] = final_price` | `new_order['final_price'] = final_price` | Evitar mutar el diccionario recibido |
| `order['status'] = 'processed'` | `new_order['status'] = 'processed'` | Mismo motivo que arriba |
| `average = total / len(processed)` | `average = total / len(processed) if processed else 0` | Evitar `ZeroDivisionError` |
| `'count': len(orders)` | `'count': len(processed)` | Contar sólo las órdenes que realmente se procesaron |

Con estas correcciones el código es más robusto, no altera datos externos y devuelve valores coherentes en todos los casos.
