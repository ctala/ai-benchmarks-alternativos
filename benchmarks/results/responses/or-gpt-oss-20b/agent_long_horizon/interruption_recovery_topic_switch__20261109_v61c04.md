### 1️⃣ Flujo típico de blog en **Notion**

1. **Crea una base de datos “Blog”** (tabla) con columnas:  
   - Título  
   - Fecha de publicación (date)  
   - Estado (Draft, In review, Published)  
   - Tags (multi‑select)  
   - Link a la página de contenido  
2. **Añade una nueva página** desde la base de datos.  
3. **Escribe en bloques**: párrafos, listas, imágenes, tablas, embeds de vídeo o tweets.  
4. **Usa la vista “Gallery”** para ver miniaturas de tus posts.  
5. **Exporta a HTML** cuando estés listo para subirlo a tu CMS (WordPress, Ghost, etc.).  
6. **Comparte** la página con tu editor o colaborador para comentarios.  

**Ventajas**  
- Todo en un solo lugar, sin mover archivos.  
- Colaboración instantánea.  
- Plantillas pre‑definidas para “Blog Post” que incluyen estructura y checklist.  

**Desventajas**  
- El “rich‑text” puede ralentizar la edición cuando el contenido es largo.  
- Exportar a Markdown/HTML requiere un paso extra.

---

### 2️⃣ Flujo típico de blog en **Obsidian**

1. **Crea un folder “Blog”** dentro de tu vault.  
2. **Nueva nota** con nombre `YYYY-MM-DD-Title.md`.  
3. **Escribe en Markdown**.  
   - Título `# Título`  
   - Metadatos frontmatter (YAML) para fecha, tags, estado.  
   - Secciones con `##` y `###`.  
4. **Usa enlaces internos** (`[[Otra Idea]]`) para conectar con otras notas.  
5. **Grafo y backlinks** te ayudan a ver cómo tu post se relaciona con otras ideas.  
6. **Exporta** a HTML o PDF con un plugin (e.g., `Markdown PDF`, `obsidian-export`).  
7. **Publica** con el plugin **Obsidian Publish** o sube el Markdown a tu CMS.  

**Ventajas**  
- **Velocidad**: Markdown es ultra ligero; la escritura es casi instantánea.  
- **Control total**: archivos de texto plano que puedes versionar con Git.  
- **Grafos de ideas**: excelente para generar contenido a partir de conexiones.  

**Desventajas**  
- No hay colaboración en tiempo real (excepto con Git).  
- Interfaz móvil limitada (solo lectura).  
- Exportar a HTML/Wordpress requiere configuración.

### 2️⃣ Flujo de trabajo recomendado (Notion como núcleo)

| Paso | Acción | Herramienta | Comentarios |
|------|--------|-------------|-------------|
| **1. Estructura de trabajo** | Crea una base de datos “Blog” con campos: Título, Fecha, Estado, Tags, Enlace a la nota. | Notion | Puedes usar la vista Kanban para mover el post por los estados (*Draft → Review → Approved → Published*). |
| **2. Redacción inicial** | El escritor (tú) crea la nota dentro de la base de datos. | Notion | Guarda borradores en la propia página. |
| **3. Envío al editor** | Cambia el permiso de la página a “Editor” y deja un comentario: “Necesito revisión, foco en tono y SEO”. | Notion | El editor recibe una notificación push/email. |
| **4. Revisión en Notion** | Editor hace comentarios inline, sugiere cambios o añade notas. Puedes usar la sección “Comments” para discutir. | Notion | Todos los cambios quedan registrados; el historial te permite revertir. |
| **5. Feedback y ajustes** | Tú haces los cambios según comentarios. Repite hasta que esté listo. | Notion | Usa la columna “Estado” para marcar “Needs Revision”. |
| **6. Exportar y publicar** | Una vez aprobado, exporta a HTML/Markdown o copia directamente al CMS. | Notion → WordPress/Ghost | Si usas **Notion Publish**, puedes publicar directamente sin exportar. |
| **7. Seguimiento de métricas** | Añade una columna “URL” y “Views” (puedes actualizar manualmente). | Notion | Puedes conectar con Google Analytics vía Zapier si quieres autom. |

### 3️⃣ Si prefieres **Obsidian + GitHub**

| Paso | Acción | Herramienta | Comentarios |
|------|--------|-------------|-------------|
| **1. Configura un repo privado** | Crea un repo en GitHub y dale acceso al editor. | GitHub | Usa ramas (`draft`, `review`, `final`). |
| **2. Redacción** | Escribe el post en Markdown en la rama `draft`. | Obsidian | Guarda los archivos localmente. |
| **3. Pull‑request para revisión** | Cuando esté listo, haz un PR de `draft` a `review`. | GitHub | El editor revisa, comenta en el PR, y sugiere cambios. |
| **4. Merge y publicación** | Una vez aprobado, mergea a `final`. | GitHub | Exporta Markdown a HTML o sube directamente al CMS. |
| **5. Historial de versiones** | Git mantiene todo el historial. | Git | Puedes revertir cualquier cambio si el editor lo necesita. |

**Ventajas**: control total de versiones, auditoría, y si tu editor ya usa Git, el flujo es natural.  
**Desventajas**: No hay comentarios en tiempo real; la comunicación se hace vía issues/PRs o Slack.

### 🎯 Cómo usar estos plugins para obtener un SEO sólido

1. **Define tu checklist SEO**  
   - Meta‑title (máx. 60 caracteres)  
   - Meta‑description (máx. 160 caracteres)  
   - URL amigable (slug)  
   - H1/H2 apropiados  
   - Alt‑text en imágenes  
   - Enlaces internos (backlinks)  
   - Keywords (primaria + LSI)

2. **Implementa la herramienta**  
   - **Notion**: Agrega los campos de SEO en la base de datos “Blog” (Title, Description, Slug). Cuando escribes, el plugin Notion SEO te da el “score” y sugerencias.  
   - **Obsidian**: Añade los campos en el front‑matter (`title:`, `description:`, `keywords:`). El plugin *Obsidian SEO* mostrará un panel con los cambios recomendados y te dirá si falta un meta‑tag o un enlace interno.

3. **Genera automáticamente la estructura**  
   - Con **Notion SEO** o **Obsidian Publish** elige “Publish” → “Generate sitemap.xml”.  
   - En Notion, el servicio de SEO también crea un sitemap opcional y te permite subirlo a Google Search Console.

4. **Enlaza internamente**  
   - En Obsidian, aprovecha los backlinks: cada vez que enlazas a otra nota, el plugin “SEO” te indicará que esos enlaces pueden mejorar el ranking.  
   - En Notion, usa la función “Mention” (`@`) para crear enlaces internos y revisa el “Page Link” en la barra de comentarios.

5. **Optimiza las imágenes**  
   - En Obsidian, añade alt‑text en el front‑matter (`alt: "Descripción de la imagen"`).  
   - En Notion, usa la extensión “Notion SEO Booster” para rellenar el campo “Alt‑text” de cada imagen.

6. **Revisa y publica**  
   - Cuando el editor aprueba el contenido, exporta a HTML (Obsidian) o publica vía Zapier (Notion).  
   - Asegúrate de que el meta‑tag y el sitemap estén presentes antes de subirlo al servidor o CMS.
