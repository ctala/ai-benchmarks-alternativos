## 📋 Desglose por Fases

### **FASE 1: Fundamentos & Copy** (Semana 1: Días 1-5)

| Día | Tarea | Responsable | Dependencias | Entregable |
|-----|-------|-------------|--------------|------------|
| 1 | Kickoff: Value prop, buyer persona, análisis competencia | Todos | - | Brief de proyecto |
| 1-2 | Arquitectura de información + Wireframes baja fidelidad | Diseñador | Brief | Wireframes (Figma) |
| 2-3 | **Copy core**: Headline hero, subheadline, 3-4 beneficios principales | Copywriter | Brief | Doc v1.0 |
| 3-4 | **Copy secciones**: Features, Pricing, FAQ, CTA, Footer | Copywriter | Wireframes aprobados | Doc v2.0 completo |
| 4-5 | Revisión conjunta + ajustes | Todos | Copy completo | **Green light para diseño** |

**⚠️ Bloqueo crítico:** El diseño UI no puede empezar hasta tener el copy aprobado (evita retrabajo).

---

### **FASE 2: Diseño Visual & Assets** (Semana 1-2: Días 5-10)

| Período | Tarea | Responsable | Dependencias | Output |
|---------|-------|-------------|--------------|---------|
| Día 5-6 | Moodboard + System Design (colores, tipografía, componentes) | Diseñador | Copy aprobado | UI Kit básico |
| Día 6-8 | **Diseño UI Desktop** (todas las secciones) | Diseñador | System design | Mockups desktop |
| Día 8-9 | **Diseño UI Mobile** + Responsive | Diseñador | Desktop design | Mockups mobile |
| Día 9-10 | **Assets de producción**: Ilustraciones, iconos, screenshots del producto | Diseñador | Mockups aprobados | Carpeta /assets |
| Día 10 | Handoff técnico (Figma → Devs) + Especificaciones | Diseñador | Assets listos | Documentación + Zeplin/Inspect |

**💡 Optimización:** El diseñador puede empezar el System Design el día 5 mientras el copywriter pulge el texto final.

---

### **FASE 3: Desarrollo Frontend** (Semana 2-3: Días 10-19)

**División de trabajo entre developers:**

**Developer 1 (Estructura & Lógica):**
- Día 10-12: Setup proyecto + Componentes base + Navbar/Hero
- Día 13-15: Secciones Features/Pricing + Formularios (captura leads)
- Día 16-17: Integraciones (Google Analytics, Hotjar, Email service)

**Developer 2 (UI Polish & Animaciones):**
- Día 10-12: Animaciones micro-interacciones + Responsive mobile
- Día 13-15: Optimización imágenes (WebP/Lazy loading) + SEO meta tags
- Día 16-17: Testing cross-browser + Performance (Core Web Vitals)

| Checkpoint | Fecha | Entregable |
|------------|-------|------------|
| MVP funcional | Día 15 | Landing navegable, falta polish |
| Beta cerrada | Día 17 | Versión staging lista para QA |

| Día | Actividad | Responsables | Detalle |
|-----|-----------|--------------|---------|

## 🔗 Mapa de Dependencias Críticas

```
[Día 1-2] Brief & Research
    ↓
[Día 2-5] Copywriting ←→ [Día 5-6] Wireframes (paralelo posible)
    ↓
[Día 6-10] UI Design High-fi
    ↓
[Día 10-17] Desarrollo ( Frontend + Integraciones )
    ↓
[Día 18-26] QA → Launch
```

**Dependencias que NO se pueden acortar:**
1. Copy → Diseño UI (mínimo 1 día de overlap, no más)
2. Diseño UI → Desarrollo (necesitan mockups finales)
3. Desarrollo → QA (mínimo 3 días de testing)

## 👥 Asignación de Roles Detallada

### **Copywriter**
- **Semana 1:** 100% dedicación (research + escritura)
- **Semana 2:** 20% (revisión diseño - ajustes de texto por espacio)
- **Semana 3:** 10% (disponible para dudas de devs)
- **Semana 4:** 30% (QA de contenido + meta descriptions)

### **Diseñador**
- **Semana 1:** 60% (wireframes + system design)
- **Semana 2:** 100% (UI completo + assets)
- **Semana 3:** 30% (support a devs, exportar assets faltantes)
- **Semana 4:** 40% (ajustes post-QA, mobile tweaks)

### **Developer 1 (Lead)**
- Enfoque: Arquitectura, componentes principales, backend forms
- Stack sugerido: Next.js + Tailwind + Vercel (deploy rápido)

### **Developer 2 (Support)**
- Enfoque: Animaciones, responsive, performance, integraciones third-party

## ⚡ Mitigación de Riesgos (Timeline Ajustado)

**Si hay retraso en diseño (Semana 2):**
- Los devs pueden empezar con el setup del proyecto y componentes genéricos (navbar, footer) usando wireframes.

**Si el copy se atrasa:**
- Usar "copy de placeholder" del brief para que diseño no se detenga, pero reservar 1 día extra en Semana 2 para ajustes finales.

**Scope creep común a evitar:**
- NO incluir: Blog, multi-idioma, dashboard interactivo, pasarela de pagos compleja.
- SÍ incluir: Hero potente, 3-4 features con iconos, pricing (si aplica), formulario de waitlist/demo, FAQ, footer.
