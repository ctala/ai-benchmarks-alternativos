## El bug: el MAD se vuelve 0 y el umbral colapsa

El algoritmo (MAD = *Median Absolute Deviation*) tiene una debilidad conocida que este código no maneja: **si la mitad o más de los valores son idénticos, el MAD es exactamente 0**.

Veamos por qué. El MAD es la mediana de las desviaciones `|x - mediana|`. Si al menos la mitad de los datos coincide con la mediana, al menos la mitad de esas desviaciones son `0`, y por tanto la mediana de las desviaciones también es `0`. Entonces:

```python
threshold = 3 * 0 = 0
filtered = [x for x in data if abs(x - median) <= 0]   # solo sobreviven los que son == mediana
```

Todo lo que no sea exactamente igual a la mediana se descarta como "outlier", **aunque no lo sea en absoluto**.

### Ejemplo concreto

```python
remove_outliers_and_average([10, 10, 10, 10, 11, 12, 13])
```

- ordenado: `[10,10,10,10,11,12,13]`, `n=7`, mediana = `10`
- desviaciones: `[0,0,0,0,1,2,3]` → MAD = `0`
- threshold = `0`
- filtered = `[10,10,10,10]`
- devuelve **10.0**, cuando la media real es **10.857...** y ninguno de los valores 11, 12, 13 es razonablemente un outlier (están a 1-3 unidades del resto).

Lo mismo pasa con `[1, 2, 2, 2, 3]` → devuelve `2.0` tirando el 1 y el 3; o con sensores que reportan muchas lecturas repetidas (`[0.5, 0.5, 0.5, 0.5, 0.6, 0.7]`), lo cual es muy común en datos reales.

### Por qué es "sutil"

- No lanza ninguna excepción: `filtered` nunca queda vacío (siempre hay al menos la mitad de los elementos con desviación `0 <= threshold`), así que la división final nunca falla.
- Con datos "bien distribuidos" (sin repeticiones masivas) el MAD es > 0 y todo funciona perfectamente.
- Solo se manifiesta cuando hay poca variabilidad / muchos valores repetidos, y el síntoma es un resultado numéricamente plausible pero incorrecto.

### Corrección típica

```python
mad = find_median([abs(x - median) for x in data])
if mad == 0:
    return sum(data) / len(data)   # o usar la desviación estándar / media de desviaciones como respaldo
```

(Algunas implementaciones usan `mean absolute deviation` como fallback cuando `MAD == 0`.)

### Bug secundario (menor)

`remove_outliers_and_average([])` lanza `ZeroDivisionError` en la primera línea (`sum([]) / 0`). Es un caso borde no cubierto, pero es un fallo "ruidoso", a diferencia del anterior que devuelve silenciosamente una respuesta equivocada.
