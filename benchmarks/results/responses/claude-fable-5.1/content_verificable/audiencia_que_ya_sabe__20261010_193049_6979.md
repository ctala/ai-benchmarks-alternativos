## Respuesta completa

**Verde no significa hecho**

Una ejecución marcada como *success* solo garantiza una cosa: ningún nodo lanzó una excepción. Nada más. Hay cuatro formas típicas de obtener ese verde sin que haya pasado nada:

1. **Cero items aguas arriba.** El nodo que debía escribir recibió un array vacío, no se ejecutó, y n8n lo registra como correcto. Un filtro mal calibrado o una query con fecha errónea bastan.
2. **Continue On Fail activado.** El nodo falló, el error viajó como item con campo `error`, y el siguiente nodo lo trató como dato normal. Nadie se enteró.
3. **HTTP 200 con error en el body.** APIs que responden `{"status":"error"}` con código 200. Para el nodo HTTP, perfecto.
4. **Rama IF/Switch sin conectar.** Todos los items cayeron en la salida que no tiene nada enganchado. Fin de la ejecución, sin ruido.

El Error Workflow no sirve aquí: no hay error que capturar.

**Cómo detectarlo**

- Al final del flujo, un nodo Code que compare `$input.all().length` con lo esperado (o con el conteo del trigger) y lance `throw` si no cuadra. Así fuerzas el rojo.
- Tras cada nodo con Continue On Fail, un IF que busque `$json.error` y desvíe a un Stop and Error.
- En llamadas HTTP, valida el body, no el status. Un IF sobre el campo relevante.
- Loguea el conteo de items por ejecución en una tabla externa y alerta cuando baje a cero N veces seguidas. Es la única forma de ver tendencias; la lista de ejecuciones no te lo muestra.

La regla práctica: nunca confíes en el color. Confía en el número de items que llegaron al último nodo.
