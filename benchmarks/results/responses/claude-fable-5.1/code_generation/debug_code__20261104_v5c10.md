# Análisis de los bugs

## Bug 1: División por cero
```python
average = total / len(processed)
```
Si ninguna orden tiene `status == 'pending'`, `processed` queda vacía y `len(processed)` es `0`. Python lanza `ZeroDivisionError` y la función falla en un caso perfectamente válido (por ejemplo, llamar a la función dos veces seguidas con las mismas órdenes: la segunda vez ya no hay pendientes).

**Solución:** calcular el promedio solo si hay elementos, y devolver `0` (o `None`, según el contrato que prefieras) en caso contrario.

## Bug 2: Mutación del diccionario original
```python
order['final_price'] = final_price
order['status'] = 'processed'
```
Los diccionarios se pasan por referencia. Al modificar `order` directamente, la función altera los objetos que el llamador le pasó, lo que produce efectos secundarios ocultos: la lista `orders` original queda cambiada aunque el llamador no lo espere, y si vuelve a procesarla, las órdenes ya no son `pending`. Esto también hace la función difícil de testear y de reutilizar.

**Solución:** crear una copia (`dict(order)` o `order.copy()`) y modificar esa copia. Si las órdenes contuvieran estructuras anidadas que también se modifican, habría que usar `copy.deepcopy`, pero aquí solo se tocan claves de primer nivel, así que una copia superficial basta.

## Bug 3: `count` incorrecto
```python
'count': len(orders)
```
El resultado describe las órdenes **procesadas** (`processed`, `total`, `average`), pero `count` reporta el número de órdenes **recibidas**, incluyendo las que no eran `pending`. Es inconsistente: `average` se calcula sobre `len(processed)` pero `count` dice otra cosa.

**Solución:** usar `len(processed)`.

# Versión corregida

```python
def process_orders(orders):
    total = 0
    processed = []

    for order in orders:
        if order['status'] != 'pending':
            continue

        # Copiamos para no mutar el diccionario original (Bug 2)
        new_order = dict(order)

        discount = new_order['total'] * 0.1 if new_order['total'] > 100 else 0
        final_price = new_order['total'] - discount

        new_order['final_price'] = final_price
        new_order['status'] = 'processed'

        total += final_price
        processed.append(new_order)

    count = len(processed)  # Bug 3

    # Evitamos la división por cero (Bug 1)
    average = total / count if count > 0 else 0

    return {
        'processed': processed,
        'total': total,
        'average': average,
        'count': count,
    }
```

# Observaciones adicionales (no son bugs estrictos, pero conviene tenerlas en cuenta)

- **Claves ausentes:** si alguna orden no tiene `'status'` o `'total'`, se lanzará `KeyError`. Podrías usar `order.get('status')` y validar `'total'` si los datos vienen de fuentes no confiables.
- **Uso de floats para dinero:** `0.1` en coma flotante produce errores de redondeo (`110 * 0.1 = 11.000000000000002`). Para cálculos monetarios suele ser mejor `decimal.Decimal` o trabajar en centavos con enteros.
- **Regla de descuento:** `> 100` excluye el caso exacto de 100. Si la regla de negocio es "a partir de 100", debería ser `>= 100`. No es un bug del código en sí, pero vale la pena confirmarlo.
