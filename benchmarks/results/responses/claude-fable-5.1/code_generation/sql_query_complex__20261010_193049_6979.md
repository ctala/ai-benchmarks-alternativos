## Entrada exacta (lo que recibió el modelo)

**user:**

Tengo estas tablas:
- orders (id, customer_id, total, status, created_at)
- customers (id, name, email, country, created_at)
- order_items (id, order_id, product_id, quantity, unit_price)
- products (id, name, category, price)

Escribe una query SQL que muestre:
- Top 10 clientes por revenue total en los ultimos 6 meses
- Con columnas: nombre, email, pais, total_orders, total_revenue, avg_order_value, categoria_mas_comprada
- Ordena por total_revenue DESC
- Solo clientes con al menos 3 ordenes completadas (status = 'completed')


## Respuesta completa

```sql
WITH ordenes_recientes AS (
    -- Órdenes completadas en los últimos 6 meses
    SELECT id, customer_id, total
    FROM orders
    WHERE status = 'completed'
      AND created_at >= CURRENT_DATE - INTERVAL '6 months'
),

metricas_cliente AS (
    -- Métricas agregadas por cliente (solo con >= 3 órdenes)
    SELECT
        customer_id,
        COUNT(*)   AS total_orders,
        SUM(total) AS total_revenue,
        AVG(total) AS avg_order_value
    FROM ordenes_recientes
    GROUP BY customer_id
    HAVING COUNT(*) >= 3
),

categoria_por_cliente AS (
    -- Revenue por categoría para cada cliente, rankeado
    SELECT
        o.customer_id,
        p.category,
        SUM(oi.quantity * oi.unit_price) AS revenue_categoria,
        ROW_NUMBER() OVER (
            PARTITION BY o.customer_id
            ORDER BY SUM(oi.quantity * oi.unit_price) DESC
        ) AS rn
    FROM ordenes_recientes o
    JOIN order_items oi ON oi.order_id = o.id
    JOIN products p     ON p.id = oi.product_id
    GROUP BY o.customer_id, p.category
)

SELECT
    c.name                      AS nombre,
    c.email,
    c.country                   AS pais,
    m.total_orders,
    m.total_revenue,
    ROUND(m.avg_order_value, 2) AS avg_order_value,
    cat.category                AS categoria_mas_comprada
FROM metricas_cliente m
JOIN customers c ON c.id = m.customer_id
LEFT JOIN categoria_por_cliente cat
       ON cat.customer_id = m.customer_id
      AND cat.rn = 1
ORDER BY m.total_revenue DESC
LIMIT 10;
```

**Notas sobre las decisiones tomadas:**

- **Revenue**: uso `orders.total` para `total_revenue` y `avg_order_value`. Si prefieres calcularlo desde `order_items` (`SUM(quantity * unit_price)`), evita hacerlo en el mismo `JOIN` que las métricas de órdenes para no duplicar filas.
- **Categoría más comprada**: la defino por revenue gastado en esa categoría. Si la quieres por cantidad de unidades, cambia el `ORDER BY` de la ventana a `SUM(oi.quantity) DESC`.
- **Filtro de 6 meses**: aplica tanto al conteo de órdenes como al cálculo de categoría, para que todo sea consistente.
- **Sintaxis de fecha**: `CURRENT_DATE - INTERVAL '6 months'` es PostgreSQL. En MySQL usa `DATE_SUB(CURDATE(), INTERVAL 6 MONTH)`; en SQL Server, `DATEADD(MONTH, -6, GETDATE())` y `TOP 10` en lugar de `LIMIT`.
- El `LEFT JOIN` con la categoría evita perder clientes si por alguna razón una orden no tuviera items.
